# Tailwind (read as Tailscale)

- Slug: tailwind
- Canonical: https://github.com/tailscale/tailscale (open-source client) · https://tailscale.com (product; docs at https://tailscale.com/docs). Brief 7.1 reads the user's "Tailwind" as Tailscale.
- Layer(s): networking
- Open source: yes (BSD-3-Clause) for `tailscaled`, the `tailscale` CLI and the client core. Closed: the Windows and iOS/iPadOS GUI wrappers ("The GUI wrappers on non-open source platforms are themselves not open source", [README L33-L36](https://github.com/tailscale/tailscale/blob/9a522a9786c97eb7910c01ccb7bd66557b04c910/README.md#L33-L36)) and the coordination service.
- Latest release checked: v1.104.1, 2026-10-07, https://github.com/tailscale/tailscale/releases/tag/v1.104.1. The tag points at `9a522a9`. The changelog says "1.104.0 was a release candidate intended for testing only". The App Store iOS/iPadOS build 1.104.1 is dated 2026-10-08. Default branch `main` was at `e3c3ef1` on 2026-10-16.
- Checked: 2026-10-19 by screen-tailwind

## Summary
- Screen: PASS
- Tailscale passes N3, N1, N2 and C1. A1, A3 and A4 are `N/A (layer)`. It is a networking component: it starts no agent sessions and never handles Claude or ChatGPT credentials, so other components must clear those gates.
- The project is healthy. It has 37.7k stars, shipped v1.104.1 on 2026-10-07 (App Store 2026-10-08), and has 462 non-bot commits to `main` in the last 90 days. In the N2 window, Brad Fitzpatrick wrote 31.7% of non-bot commits, Simon Law merged other people's PRs, and Nick O'Neill tagged the releases. The vendor is Tailscale Inc.
- C1:
  - Windows: a native Windows 10/11 client. Turn on "Run unattended" on the always-on PC, because by default it disconnects when the user signs out.
  - iPhone/iPad: one App Store app for both (iOS 16.6+).
  - WSL2: Tailscale says to run it on the Windows host only, not also inside WSL2. WSL2 services reach the tailnet through the host, via WSL localhost forwarding (NAT mode) or mirrored mode.
- For composition, Serve (GA) is the strongest fact (F6). `tailscale serve --bg <port>` on Windows gives a tailnet-only HTTPS URL that iPhone Safari can open. Through WSL localhost forwarding this also covers a dev server inside WSL2. Caveat: open issue #9228 reports 502s on the Windows → WSL2 path, with an MTU workaround.
- Taildrop (F8) and Taildrive (A5/F7) are both **alpha and opt-in**, so they score PARTIAL under 7.16a. With Taildrive, the iOS Files app can browse and edit folders shared from Windows, but iOS cannot share folders. Neither has evidence that Windows can share a WSL2 path.
- Tailscale SSH has a server on Linux and macOS only. On this PC it would need `tailscaled` inside WSL2, which Tailscale advises against. Plain SSH over the tailnet works, but needs an iOS SSH app screened as glue. iOS allows only one VPN at a time.

## Open questions
- **Serve on Windows to a WSL2 dev server.** Does it work end to end on v1.104.1 from an iPhone, or does the #9228 502/MTU failure occur? iOS cannot lower its MTU.
  - Why it matters: this is the main F6 path. A live test or a maintainer statement would settle it.
  - Fallback: mirrored mode with direct tailnet-IP access (#14790).
- **WSL2 paths in Taildrive or SMB.** Can Windows Taildrive (`tailscale drive share`) or a Windows SMB share expose a WSL2 ext4 path (`\\wsl.localhost\<distro>\...`)?
  - Why it matters: if not, Tailscale gives A5/F7 only for workspaces on the Windows filesystem, which Microsoft advises against for Linux tooling. Running `tailscaled` inside WSL2 to share Linux paths conflicts with Tailscale's run-on-the-host-only advice.
- **Taildrop default.** Is Taildrop still opt-in for new tailnets? The doc was validated 2026-01-05.
  - Why it matters: under 7.16a an alpha label alone is only a caveat if the feature ships enabled by default. Opt-in keeps F8 via Taildrop at PARTIAL.
  - Taildrive stays PARTIAL either way, because it needs policy-file `nodeAttrs`.
- **SMB from iOS Files over the tailnet.** Does it work reliably, especially on cellular (#18967)?
  - Why it matters: it would give a non-alpha A5/F7/F8 path built only from givens (Windows SMB and the iOS Files app). It is UNKNOWN until shown end to end.
- **Tailscale SSH Console on iOS Safari.** Does it work there?
  - Why it matters: without it, SSH from iPhone needs a separately screened iOS SSH app (A1 via a generic terminal, 7.4).
