## Summary
- Screen: HOLD (A1, A3, A4).
  - The hold is structural. This component runs only Codex, and 7.4 and 7.6 assign Claude Code to a partner component (e.g. claude-desktop).
  - Every Codex-side check passes with the Windows-native agent. The exception is the WSL2 agent mode (A1, below).
- **Deep-dive (2026-10-19, deepdive-chatgpt-desktop-codex):**
  - **Component-level ALWAYS gates,** for the recommended Windows-native topology (T-W, below):
    - A2 PASS for host threads. Codex cloud tasks are UNKNOWN.
    - A5 PASS for folders saved as projects on the host, through the iOS workspace file browser.
    - A6 PASS (workaround), both directions, with a Windows-native `claude` partner.
    - A7 PASS (workaround).
    - A8 PASS (workaround), both directions.
    - A1, A3 and A4 stay PARTIAL. The component runs only Codex, and the 7.16 clarifications change nothing here.
  - **FAVOUR:** F1–F10 = 11/20; F11a–e = 5/10.
  - **Fact that most affects composition:**
    - The Windows app and the native Windows Codex CLI share `%USERPROFILE%\.codex`, covering config, cached auth and session history.
    - OpenAI staff say CLI sessions appear in the app once their original-cwd project is added.
    - So a Windows-native topology keeps Claude-launched `codex exec` runs in the same login and store that the app and the phone use. That means repos on `C:\` and both CLIs installed natively.
    - WSL2 breaks this unless `CODEX_HOME` points at the Windows home, and the WSL agent's remote control is unreliable.
    - Still UNKNOWN: whether the app lists `exec`-source threads. The app-server's default thread list covers interactive sources only.
- **Maintenance (N1–N3).** OpenAI ships this weekly, and N1 does not apply (closed source).
  - Desktop app 26.1007 (2026-10-08) and a Store update on 2026-10-17. ChatGPT iOS 1.2026.279 (2026-10-16).
  - "Codex app" merged into the ChatGPT desktop app on 2026-07-09. It is the same Store package, renamed, not deprecated.
- **Windows PC (C1).** The app installs natively (Store or winget, Windows 10 19041+, x64) and runs its Codex agent either Windows-native (PowerShell plus the Windows sandbox) or inside WSL2, switched in Settings.
  - The app is a GUI process; tray residency has been supported since 26.401. Remote access stops if the PC sleeps, loses network or the app is closed.
  - No service mode is documented.
- **iPhone (A1, Codex half).** ChatGPT iOS (Codex tab) pairs with a Windows host by QR code. From the phone the user can:
  - list hosts and chats, and follow them live;
  - send follow-ups, answer questions and approve commands;
  - start new chats in a host project, or in a folder chosen with a directory picker (since iOS 1.2026.160).
  - Codex cloud tasks can be started and followed from the phone too. The App Store app supports iPad, and has an iPad split view since iOS 1.2026.258 (lead for F3/F4).
- **WSL2 caveat.** OpenAI documents remote hosts only as "the ChatGPT desktop app on macOS and Windows" and says nothing about the WSL agent mode. User issues show a separate "WSL remote host" that works but goes offline (#49436, open). They also show failures starting new tasks for WSL2 UNC projects from Android (#40519, open). WSL agent mode itself broke completely on 26.928–26.1007 (#49731, closed 2026-10-12).
- **Codex path (A3/A4).** The unmodified Codex harness runs on "Sign in with ChatGPT", which gives subscription access.
  - Mobile remote control and Codex cloud are "unavailable" with an API key; API-key sign-in is "Sign in another way" in the app and must be avoided.
  - The app runs no Claude Code. Its "Import" feature only imports Claude Code setup and recent work into Codex.

### Harness integration (from source and docs)
- **How it invokes `codex`:**
  - The app runs the bundled engine itself: "By default, the ChatGPT desktop app uses the Windows-native Codex agent". In WSL mode, "the agent itself" runs in WSL2.
  - For SSH hosts, "The app starts the remote Codex app server through SSH".
  - The app is closed, so its process model can't be confirmed from source. Its protocol (app-server) is open, and the session store it writes is open.
- **How it invokes `claude`:** it doesn't. "Import" only copies Claude Code setup into Codex (screen).
- **OAuth credentials:**
  - Sign in with ChatGPT happens in the app.
  - On Windows the app shares `%USERPROFILE%\.codex` (including `auth.json`) with the native CLI, by vendor design. `auth.json` "contains access tokens", so treat it like a password.
  - No third-party read, copy or proxy is involved, so the 7.16b note is not needed.
- **Transcripts:**
  - Files: `$CODEX_HOME/sessions/…/rollout-<timestamp>-<id>.jsonl` and `$CODEX_HOME/archived_sessions/` (`lib.rs#L86-L87`). `recorder.rs` L1 says: "Persist Codex session rollouts (.jsonl) so sessions can be replayed or inspected later".
  - Rollouts are zstd-compressed after 7 days.
  - Sources: `SessionSource` is one of `Cli`, `VSCode`, `Exec`, `Mcp`, `Custom`, `SubAgent`, … ([protocol.rs#L2959-L2970](https://github.com/openai/codex/blob/89461ea6833832b0551ce24ee32205824d5c108d/codex-rs/protocol/src/protocol.rs#L2959-L2970)). The interactive set is `Cli`, `VSCode`, `atlas` and `chatgpt`.
- **Do the CLI and the app share a store?**
  - Yes on native Windows: the same `%USERPROFILE%\.codex`.
  - Not in WSL by default: "the CLI uses the Linux home directory by default … so it doesn't automatically share configuration, cached auth, or session history with the Windows app". The fix is to set `CODEX_HOME` to the Windows home.

### Stack fit
- **Covers:** the Codex half of A1, A3 and A4. Also A2 for Codex threads; A5 for host project folders through the phone file browser; the Codex side of A6–A8; and F3, F4 and F5.
- **Needs:**
  - (1) claude-desktop for the Claude half of A1, A3 and A4, and the Claude half of F10.
  - (2) A networking partner for F6 (tailwind/Tailscale, pending screen).
  - (3) Optionally agentview-b, to render cross-harness child transcripts (F11c).
  - (4) Optionally openai/codex-plugin-cc as Claude→Codex glue, which needs a 7.12 screen.
- **Recommended topology T-W (Windows-native).** This matches claude-desktop's T-W.
  - **Install:**
    - The ChatGPT desktop app (Store or winget) with the Windows-native agent, which is the default.
    - The Codex CLI natively on Windows, which shares `%USERPROFILE%\.codex` with the app.
    - Claude Desktop and the Claude Code CLI natively on Windows.
    - Repos under `C:\…`, each added as a project in the ChatGPT app and used by both harnesses at the same paths. That keeps the cwd matching that #21079 says decides app visibility.
  - **Phone:** go to Settings > Connections > Control this Mac or PC, pair by QR, and enable keep-awake. Set Windows power settings to never sleep. "Prevent sleep while running" is documented for macOS and Linux only.
  - **Cross-harness:**
    - Claude's shell runs `codex exec --json -C <repo> --sandbox workspace-write [--add-dir <handover>] "<task>"`, never with `--ephemeral`.
    - Codex runs `claude -p … --output-format stream-json --verbose` after an approval. Add an "Always approve" or a `prefix_rule` for `claude`; rules are experimental, so approvals are the default path.
  - **WSL2:**
    - Use it only for Linux tooling, through `wsl` from the Windows agent: "The app can still work with projects that live in WSL2 by using the `wsl` CLI when needed".
    - Keep cross-harness calls off the WSL boundary.
- **Alternatives if repos must live in WSL2 ext4:**
  - (a) WSL agent mode. Its remote control is undocumented, and the open bugs are #49436 and #40519.
  - (b) SSH-host mode into an sshd in WSL2. Untested for WSL; the doc says the "phone still connects to the same host".
  - (c) In either case, point `CODEX_HOME` at `/mnt/c/Users/<u>/.codex` so the stores stay shared.
- **Conflicts and caveats:**
  - The app must stay running (tray is fine).
  - Mobile remote control is listed for Plus, Pro, Business and Enterprise, and not for API keys. Workspace admins may need to enable it.
  - Signing out turns Remote Control off.
  - Re-pair if a connection hasn't been used since 2026-06-08.
  - With many unarchived threads, remote use degrades (#45246, open).
  - Computer Use on a Windows host runs in the foreground.

## Open questions
- **Does iOS remote control officially support a Windows host whose agent runs in WSL2?**
  - The docs are silent. Issues show a separate "WSL remote host" that works but drops offline (#49436) and fails to start new tasks on WSL2 UNC projects (#40519, Android).
  - Why it matters: A1 (agent in WSL2) goes from PARTIAL to PASS. It also decides whether the stack should keep Codex Windows-native with repos on the Windows drive (`/mnt/c` from WSL), which is the documented, reliable path.
  - Settled by: an OpenAI doc statement, or a hands-on test on build 26.1013 or later from an iPhone.
- **Does the app start at Windows sign-in, and does remote control come back on its own after a reboot or Windows Update?** Pairing survives sign-out, but "Signing out of ChatGPT turns off Remote Control" until it is turned on again.
  - Affects: the C1 unattended note and A1 reliability on the always-on PC, not the verdicts.
- **Is the CLI's headless `codex remote-control` usable inside WSL2?**
  - Source marks it "[experimental] Manage the app-server daemon with remote control enabled." (https://github.com/openai/codex/blob/89461ea6833832b0551ce24ee32205824d5c108d/codex-rs/cli/src/main.rs#L177-L178, 2026-10-19).
  - The docs say mobile setup "can't" start from the CLI, and WSL2 bugs are open (#52099, #45674). Docs and source conflict.
  - Why it matters: it is the only path with no GUI. It is out of scope for this component (the CLI is a given), but it would change the unattended note for any Codex-in-WSL2 stack.
- **Do sessions that the app did not start appear in its thread list and on the phone, and can they be continued there?** Examples: `codex exec` launched by Claude Code in WSL, or a WSL CLI with `CODEX_HOME=/mnt/c/Users/<u>/.codex`.
  - #47454 reports a WSL2 CLI session "continued through ChatGPT Remote on a phone", path unknown.
  - Affects: F10, F11b–F11e, A8 and A2 (iPhone visibility) at deep-dive.
- **Does the phone show each tool call (command and output) at full fidelity, or only summaries?** The docs list "terminal output", and the desktop has a "Thread detail" setting for how much command output threads show.
  - Affects: the A2 iPhone note and F11e.
- **Does the iOS workspace file browser (1.2026.160, "previewing files and linking workspace paths into prompts") cover the whole project tree, including uncommitted files?**
  - Affects: A5 and F7 at deep-dive.
- **Orchestration impact (later stages).** `codex mcp-server` was removed on 2026-09-05. The changelog says to "Use the Codex app server for integrations", but "The app-server command is experimental and isn't supported for production workloads."
  - Affects: the design of A8 (Claude→Codex create, monitor, resume) for any stack using this component. `codex exec`/`resume` remain.
- **Remote at scale.** #45246 (open, 2026-09-13) reports remote control "unusable from mobile when host has many unarchived threads".
  - Affects: A1 reliability for heavy use, not the verdict.
