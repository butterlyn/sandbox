## Summary

  - The hold is structural. Codex is not covered, and 7.4 and 7.6 assign Codex to a partner component.
  - Every Claude-side check is PASS, and no further evidence about this component would lift the hold.
  - Pairing with a Codex component (e.g. chatgpt-desktop-codex) settles it at stack level.
- **Deep-dive (2026-10-19):**
  - Component-level ALWAYS gates:
    - A2 PASS. iPhone fidelity is PARTIAL: iOS truncates approval commands and diffs.
    - A6 PASS (workaround), local topology, both directions. The cloud topology fails A6a.
    - A7 PASS (workaround). A8 PASS (workaround), both directions.
    - A5 PARTIAL: from the iPhone you see only diffs, path autocomplete and agent-relayed reads.
    - A1, A3 and A4 stay PARTIAL: the component is Claude-only, and 7.16 changes nothing here.
  - FAVOUR: F1–F10 = 12/20, F11a–e = 5/10.
  - Partners needed: a Codex component for A1/A3/A4, and a file-visibility partner for A5 (plus F6–F8).
- **Maintenance (N2, N3).** This is an active vendor product with many staff working on it.
  - Claude Code shipped 74 releases in the last 90 days (latest 2.1.303, 2026-10-18).
  - Windows Desktop 2.42304.2 shipped 2026-10-19 and the iOS app 2026-10-17.
  - N1 does not apply (closed source).
- **Dispatch is closed to new users.** The Help Center says (2026-10-15): "Dispatch isn't available to new users. If you already use Dispatch, you can keep using it for now".
  - It is recorded as N3 FAIL and excluded from the component.
  - The phone→PC paths that replace it are Remote Control and cloud sessions, both in scope.
  - The Claude Code docs still describe Dispatch without this note (conflict recorded).
- **Windows PC (C1).** A native Windows Desktop app whose Code tab runs Local, WSL 2 (not labelled beta), SSH and Cloud sessions. The `claude` CLI is supported natively and inside WSL 2.
  - WSL sessions lack the integrated terminal, connectors and plugins, forking, the file browser pane, `@` suggestions and `/resume`.
- **iPhone/iPad (A1).** One universal Claude app plus claude.ai/code.
  - The user can list sessions and read live transcripts, message a session, answer permission prompts and start new sessions.
  - A new session can go to a cloud environment (pick a GitHub repo and branch) or to a PC folder. On the PC (Windows or WSL2) that folder must be served by a running `claude remote-control`. The PC-side `claude` process (Desktop app open, or the CLI) must keep running.
- **Claude path for A3/A4.** First-party Desktop, CLI and cloud on claude.ai OAuth; Remote Control rejects API keys.
  - Remote Control: Pro and Max; Team and Enterprise only when an admin enables it.
  - Cloud sessions: Pro, Max and Team; Enterprise with premium or Chat + Claude Code seats.
  - Dispatch: Pro and Max only (limited beta, now closed to new users).

### Harness integration (from source)
- **Source is unavailable.** Claude Desktop, the iOS app and the Claude Code binary are closed. anthropics/claude-code holds only plugins, examples and the changelog ("© Anthropic PBC. All rights reserved."), so there are no permalinks to integration code. The bullets below rely on Anthropic's primary docs.
- **How it invokes `claude`.**
  - *Desktop Code tab:* "runs its own copy of Claude Code … The desktop app downloads and updates that copy". It shares configuration and CLAUDE.md with the CLI ("They share configuration and project memory via CLAUDE.md files"). In WSL 2 environments, "The session's Claude Code process, its tools, and git all execute inside the distribution".
  - *Remote Control:* the user runs the unmodified CLI (`claude remote-control [--spawn same-dir|worktree|session] [--capacity N]`, `claude --remote-control`, `/rc`). The phone and web are "a window into that local session".
  - *Cloud sessions:* Claude Code runs on Anthropic-managed VMs, started from the app, web, Desktop or `claude --cloud`.
- **How it invokes `codex`:** it doesn't. Codex is reachable only as a subprocess the agent runs (`codex exec`), using the codex CLI's own login.
- **OAuth credentials:** first-party only.
  - Claude Code stores the user's login in `%USERPROFILE%\.claude\.credentials.json` (Windows) or `~/.claude/.credentials.json` (Linux, file mode 0600) and manages it through `/login` and `/logout`.
  - Desktop and cloud "use OAuth" and ignore `ANTHROPIC_API_KEY`, `ANTHROPIC_AUTH_TOKEN` and `apiKeyHelper`.
  - Remote Control rejects API keys.
  - Cloud "network secrets" are attached outside the sandbox and apply only to keys the user adds.
  - No third-party read, copy or proxy is involved, so no 7.16b policy-risk note is needed.
- **Transcripts it produces:**
  - Local: `~/.claude/projects/<project>/<session>.jsonl` (Windows: under `%USERPROFILE%\.claude\`). Subagents go under `<session>/subagents/` and phone uploads under `uploads/<session>/`.
  - Remote Control sessions: a synced copy is "stored on Anthropic servers" while connected.
  - Cloud sessions: kept server-side, retrievable with `--teleport`.

### Stack fit
- **Covers:** client/UI (Desktop plus a universal iOS/iPadOS app), Claude-side orchestration (`--cloud`, `--bg`, cross-session messaging, Projects beta), the first-party cloud runtime, and the Remote Control relay. That fills every Claude-side need for A1–A4 and A6–A8.
- **Needs:**
  - (1) A Codex component for A1, A3 and A4. chatgpt-desktop-codex is the natural pair: its screen PASSes every Codex check with the **Windows-native** agent.
  - (2) A file-visibility partner for A5, plus F6–F8, e.g. Tailscale with the Windows SMB share and the iOS Files app (7.12 givens), or obsidian-sync, pending their screens.
  - (3) Optionally agentview-b, to render both harnesses' transcripts for delegated runs (F11c).
- **Recommended topology (T-W, Windows-native):**
  - **Install:** Claude Desktop and the Claude Code CLI on Windows (Git for Windows). Keep repos on the Windows drive, which matches the setup chatgpt-desktop-codex documents as reliable.
  - **Phone access:** in Desktop, **Settings > Claude Code**, turn on **Connect new sessions to Remote Control**. Also turn on **Use this computer from your phone and claude.ai** and list the project folders, so the phone can start sessions there ("Threads can run on this computer while the app is open").
  - **Optional per-repo servers:** `claude remote-control --spawn worktree --name <repo>`.
  - **Server supervision:**
    - Run the servers with a Task Scheduler logon task in a restart loop; Anthropic documents no service mode.
    - A loop is needed because server mode "gives up after roughly 10 minutes" offline and exits; `--continue` restores the session within ~4 hours.
    - Trust each folder interactively once first: with no TTY the command "exits with a `Workspace not trusted` error", and trust is never saved for the home directory.
  - **Settings:** set `cleanupPeriodDays` high in `%USERPROFILE%\.claude\settings.json`. Never set `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC` (it disables Remote Control) or API-key variables.
  - **Codex side:** the ChatGPT desktop app's Windows-native agent, with the codex CLI on Windows signed in with ChatGPT. Whether the app and the CLI share `%USERPROFILE%\.codex`, so that delegated `codex exec` threads appear in the app and on the phone, is for the chatgpt-desktop-codex deep-dive.
  - **Cross-harness:** Claude's shell tool runs `codex exec …`, and Codex runs `claude -p …`, both on shared `C:\` paths.
  - **Power:** the PC must not sleep. Remote Control reconnects after wake, but phone access needs a running process.
- **Alternative topology (T-L, WSL2):**
  - Run `claude remote-control` inside WSL2 under a systemd user unit with `Restart=always`. WSL supports systemd (learn.microsoft.com/windows/wsl/systemd); Anthropic documents tmux or screen, not services.
  - Keep repos on ext4, not `/mnt/c`: #70750 is a launch failure on `/mnt/c`.
  - Costs:
    - Desktop WSL sessions lack the file pane, `/resume` and the terminal, and their Remote Control is undocumented;
    - F10 drops to remote listings only;
    - WSL push notifications don't arrive (#96568);
    - Codex's phone remote is unreliable with a WSL2 agent (chatgpt-desktop-codex screen), so cross-harness calls would cross the WSL boundary (`codex.exe` / `wsl.exe` interop).
- **Conflicts and caveats:**
  - Two `claude remote-control` servers in one folder collide ("Remote Control not started here").
  - Plans: Remote Control needs Pro or Max (on Team or Enterprise, admin-enabled); Projects is Pro/Max only. Dispatch stays excluded (N3).
  - iOS truncates approval commands at about 100 characters (#37235), so approve risky commands from the PC or rely on permission rules or auto mode.
  - The Anthropic `claude -p` subscription allowance has a paused, previously announced change that could return.
