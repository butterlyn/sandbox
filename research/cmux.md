# cmux

- Slug: cmux
- Canonical: https://github.com/manaflow-ai/cmux ; https://cmux.com (docs index https://cmux.com/llms.txt, iOS docs https://cmux.com/docs/ios). Found while checking C1: the Linux TUI package https://www.npmjs.com/package/cmux (source `cmux-tui/` in the same repo) and the Linux browser nightly https://cmux.com/linux (distribution repo https://github.com/manaflow-ai/cmux-v2).
- Layer(s): client/UI (PC terminal; iPhone companion), orchestrator (light: CLI and Unix-socket API), runtime/sandbox (cmux Cloud VMs, early access)
- Open source: yes. The app is GPL-3.0-or-later. The server parts (`web/`, the Cloudflare workers and the relay services) are BUSL-1.1, which is source-available and counts as open source under 7.3. The `cmux-tui` crates and the npm `cmux` package are MIT.

  - cmux TUI cmux-tui-v0.13.4, 2026-09-17, https://github.com/manaflow-ai/cmux/releases/tag/cmux-tui-v0.13.4 (npm `cmux` 0.13.4, dist-tag `latest`).
  - iOS "cmux BETA" 1.0.6 (TestFlight only), 2026-09-23, per https://github.com/manaflow-ai/cmux/blob/42048bddfc8dc622ee13f43886084270ce836524/ios/CHANGELOG.md#L45-L58.
  - cmux Browser Linux x64 nightly 151.0.7922.64 (pre-release), 31 Jul 2026, https://github.com/manaflow-ai/cmux-v2/releases/tag/nightly.

## Summary
- Screen: FAIL at C1. This covers cmux as scoped in 7.19: the macOS terminal app with its socket API and CLI, and its iOS companion.
- Sub-component cmux-tui (`npx cmux`, cmux's Linux TUI multiplexer, found while checking C1): HOLD (A1).
  - N1–N3 PASS (same repo); C1 PASS (via WSL2); A3/A4 PASS; A1 PARTIAL.
  - It is not the scoped product. The orchestrator decides whether to admit it as a stack component (7.12).
- **Why the scoped product fails C1.** The user has no Mac (7.9), and every part of the scoped product needs one:
  - The app is "macOS only, for now" (Swift/AppKit), and v0.65.2 ships only macOS DMGs.
  - The iOS app "is a companion for your Mac" and connects "only to Stable or Nightly Mac builds".
  - `cmux ssh`, which can run agents on a remote Linux host such as WSL2, is driven from the Mac app. So is cmux Cloud.
- **What does run on the PC.** cmux-tui ships official static-musl Linux x64/arm64 builds on npm (0.13.4, 2026-09-17), and its docs send Windows users to WSL 2. In WSL2 it can fill the layer tmux fills:
  - durable headless sessions;
  - a CLI and control socket that agents can drive;
  - `claude`/`codex` shims that add only hooks.

  Its gap is the phone. No released cmux client reaches it, so A1 needs a screened iOS SSH terminal, as with tmux. The Linux "cmux Browser" is nightly-only (C1 PARTIAL) and is not a route.
- **Earlier checks pass:**
  - N3: v0.65.2 published 2026-10-16, with 13,205 non-bot commits to `main` in the last 90 days.
  - N1: 28.3k stars.
  - N2: four humans each wrote at least 10% of the 17,656 non-bot commits since 2026-04-22.
- **Watch item.** Direct SSH from the cmux iOS app to "any computer" was merged on 2026-09-28: plain shells, tmux and cmux-tui, with "no paired cmux Mac in the middle" and no cmux account needed. It is in no documented release. If it ships, re-screen C1 and A1 for cmux iOS plus cmux-tui (or tmux) in WSL2.

## Open questions
- **Which layers would cmux fill if the user added a Mac?** This matters only if the user's setup changes, since C1 fails for the scoped product today. Leads, not verdicts:
  - **PC terminal (on the Mac).** `cmux ssh` would front the always-on PC: agents run in WSL2 and the Mac app uploads `cmuxd-remote-linux-*`. This needs sshd in WSL2 and a network path such as Tailscale.
  - **Light orchestrator.** The socket API and CLI cover splits, send-keys, screen reads and the browser. Remote processes "can run cmux commands that execute on your local instance", and Claude Code teammates appear as native splits.
  - **iPhone client.** The TestFlight iOS app pairs through Mobile Connect. It would score F3 PARTIAL (TestFlight), and A1 would be PARTIAL under 7.16a while it stays TestFlight-only and Founder's-gated.
- **What are the Windows/WSL2 counterparts?** The user named wmux and tmux; leads only.
  - wmux-a (openwong2kim) and wmux-b (amirlehmam); wmux-b advertises a cmux-compatible socket API.
  - tmux in WSL2.
  - This screen adds a fourth, from the same vendor: cmux-tui in WSL2. Should cmux-tui be admitted as a stack component (7.12)? It cleared N1–N3 and C1 above on primary evidence. Its A1 depends on a screened iOS terminal (ios-terminal T1/T2), exactly like tmux.
- **When will the cmux iOS app's direct SSH ship?** Commit #14149 (2026-09-28) adds SSH to "any computer" with plain, tmux and cmux-tui hosts: "No iroh, no cmux relay, no paired cmux Mac in the middle". The PRD's status line still reads "D8 SSH library spike next".
  - If a public build ships it and cmux.com documents it, re-screen. cmux iOS plus cmux-tui (or tmux) in WSL2 could then cover A1 with cmux's own app.
  - The verdict would stay PARTIAL while the app is TestFlight-only (7.16a). F3 would be PARTIAL, and F4 is a lead (iPhone and iPad, hardware keyboard).
- **Will the iOS app reach the App Store?** `CMUX_IOS_APPSTORE_MARKETING_VERSION = 1.0.0` and early-October App Store export fixes suggest a first release is being prepared, but no listing exists today. A listing would change F3, and with direct SSH, A1. The App Store apps named "Cmux Remote", "CmuxPhone" and "Telecmux" are by other developers: unaffiliated, leads only.
- **Is cmux-tui a supported product?** The site never mentions it, and the TUI nightly channel was retired as "dormant" on 2026-10-05. The stable npm/PyPI release path is active (0.13.4, 2026-09-17), and the vendor PRD calls it "shipped". A stricter reading that treats an unadvertised package as non-GA would move its C1 to PARTIAL.
- **How does cmux-tui stay up on an always-on PC?** There is a headless owner mode, but the README says "Detached local startup is deferred until cmux has an explicit supervisor and readiness contract", and cmux.com documents no service unit. The user would supervise it, e.g. with a systemd user unit in WSL2. This bears on the 7.4 persistence condition for A1 and on the C1 unattended note.
- **How concentrated is cmux-tui's maintenance?** 93.9% of commits touching `cmux-tui/` since 2026-04-22 are by Lawrence Chen, and the last three cmux-tui tags are his. Austin Wang authored the latest cmux-tui PRs. N2 passes at repo level. A per-directory N2 would need PR "merged by" data.
- **What are chatmux, `cmux-relay` and `machine-agent`?** Leads, not screened:
  - npm `cmux-relay` 0.0.13 says "Securely pair a computer with chatmux and keep it online as a target". Its Rust port is 0.1.0-rc.6 on `next`. chatmux is a separate Manaflow product with no public docs found.
  - `npx cmux machine-agent` (Unix-only) shares a local cmux-tui session with cmux.cloud through an outbound SSH registration and a one-time pairing code. The session is then reached through `ssh cmux.cloud`, which still needs an SSH client on the phone. Plan requirements are unknown.
  - Either could become a no-Mac phone path. If so, re-screen A1 and C1.
- **Ungraded observations for any Mac-based re-screen (A3/A4):**
  - The Mac app hosts unmodified CLIs in its terminals.
  - It also has a `CodexAppServerSession`, which "does not own ChatGPT refresh credentials" per the design note.
  - cmux Cloud runs Claude Code, Codex and others on Manaflow-hosted VMs and lets them "use your own sign-in" (#20069, 2026-10-13). That is the 7.6 third-party-hosted row: A3 PARTIAL unless an approved arrangement is documented.
  - A skills.sh lead says the app attaches a computer-use MCP server to the agent sessions it launches. Check that this is additive (A4).
