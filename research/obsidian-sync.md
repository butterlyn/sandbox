- N1 is N/A because every part is closed source. N2 passes: Obsidian's about page names seven staff, and both the App Store seller and the headless package author are Dynalist Inc.
- C1 passes on generally available builds: a native Windows installer and one universal App Store app for iPhone and iPad, both with Sync built in.
  - Sync runs only while Obsidian is running ("No, files are only synced when Obsidian is running").
  - So the Obsidian window must stay open on the PC, and the iPhone/iPad syncs only while the app is open.
- The official headless client (`ob sync --continuous`, Node ≥22) runs unattended on Linux, and so in WSL2.
  - Obsidian labels it "open beta" (version 0.0.x).
  - It has open issues reporting deleted files and missed changes.
  - A stack that relies on it gets PARTIAL for that path under 7.16a.
- A1, A3 and A4 are N/A (layer): it syncs vault files and launches no agent sessions.
- Main caveats for A5 (graded at stack level, not here):
  - Files and folders whose names start with `.` never sync. The docs name `.git`, `.gitignore` and `.vscode`.
  - Code files sync only after "Sync all other types" is enabled on every device.
  - Single files are capped at 5 MB (Standard) or 200 MB (Plus).
  - Conflicts in non-Markdown files resolve as "last modified wins".
  - The Windows app cannot open a vault on `\\wsl$`; that has been an open feature request since 2020. A WSL2 workspace therefore has to live on NTFS (`/mnt/c`, which Microsoft advises against for Linux tools) or depend on the beta headless client.
  - A repo synced this way arrives on the iPhone as plain files, without its git metadata.

## Open questions
- **Headless "open beta" under 7.16a.**
  - The facts: the docs label it "(open beta)", the version is 0.0.x on npm `latest`, and the changelog entry announcing it is tagged "public". It needs no waitlist or flag.
  - Read here as a beta build, so any stack path that needs a vault living in WSL2's own filesystem is PARTIAL.
  - If "open beta on the public channel" counts as "ships in the stable public release with a beta label", that path is PASS with a caveat.
  - This changes the stack's A5 path through WSL2, not this screen's outcome.
- **`\\wsl$` vault in the Windows app.**
  - No vendor statement covers 1.14.4.
  - The 1.13.5/1.13.6 network-drive fix may or may not cover `\\wsl.localhost`.
  - A test on the user's PC would settle it. It matters for A5 and F7: whether agent workspaces in the WSL2 filesystem can be the vault without the beta headless client.
- **"Same device" warning.** Obsidian does not say whether Windows and its WSL2 distro count as one device. This matters if headless runs in WSL2 while the desktop app syncs on Windows, especially for the same remote vault.
- **Files added through the iOS Files app.** No doc says whether files placed in the vault folder this way are detected and uploaded. This decides F8 (M1 → M2) through this component.
- **Large repos.**
  - No file-count limit or performance guidance is documented.
  - A5 needs workspace files to sync within minutes, so a real repo should be tested with "Sync all other types" on and build folders excluded.
- **No background sync on iPhone/iPad.** The docs say none happens. Any stack claim that M1 sees M2 changes without the user opening Obsidian cannot rest on this component.
