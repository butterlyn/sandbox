## Summary
- Screen: SCREEN HOLD (A1)
- **Healthy AWS Labs project with several maintainers (N3, N1, N2 PASS).**
  - Not archived, with no deprecation wording. v2.5.4 shipped 2026-10-15.
  - `main` has 225 non-bot commits from 49 authors in the last 90 days, the latest on 2026-10-19. 1.5k stars.
  - Since 2026-04-22, Stan Fan wrote 20.3% and Ted Swinyar 11.5% of non-bot commits. haofeif and fanhongy (Stan Fan) published the releases.
- **PC side runs in WSL2 (C1 `PASS (via WSL2)`).**
  - The package refuses native Windows, saying "On Windows, run CAO under WSL2".
  - PyPI ships a Linux x86_64 wheel, and the docs give apt commands for tmux.
  - `cao-server` is a foreground process with no documented service mode.
- **Both harnesses run natively on the user's own logins (A3, A4 PASS).**
  - CAO types the unmodified interactive `claude` and `codex` TUIs into tmux panes.
  - It never sets, reads or injects API keys or credential files, and makes no model calls of its own. Its memory compiler shells out to the same CLIs.
  - Profile prompts are appended: `--append-system-prompt-file` for Claude, `-c developer_instructions` for Codex.
  - **Docs conflict:** the installation page says Claude Code "requires Anthropic API key" and Codex "requires OpenAI API key". The provider guides say "API key or … subscription". The source decides.
  - **Setup:** log in with `claude` `/login` and `codex login` (ChatGPT), and keep `ANTHROPIC_API_KEY`, `ANTHROPIC_AUTH_TOKEN`, `apiKeyHelper` and `OPENAI_API_KEY` unset. The Claude guide's `claude setup-token` route does not work under CAO, because the launcher unsets every `CLAUDE*` variable, including `CLAUDE_CODE_OAUTH_TOKEN`.
- **Phone access is partial (A1 PARTIAL, not a hard fail).**
  - The web UI implements (i)–(iii) for both harnesses: a session list, live xterm.js terminal and output viewer; a Quick Send message box plus live keystrokes; and a "Spawn Agent" form with provider and working directory.
  - Remote use is documented but not the default: `--host`, Host and WebSocket client allowlists, and a local token.
  - Nothing documents phone use, Tailscale is named only for fleet nodes, and the layout is desktop-first.
  - Sessions are still reachable from an iPhone, through the web UI or through tmux attach (7.4).
- **Defaults to note:**
  - Every launch bypasses approvals (`claude --dangerously-skip-permissions`, `codex --yolo`).
  - The API has no authentication unless `CAO_AUTH_LOCAL_TOKEN` or an IdP is set.
  - CAO writes `skipDangerousModePermissionPrompt: true` into `~/.claude/settings.json`.
  - PyPI says "Development Status :: 4 - Beta" (a 7.16a caveat, not a gate change).
- **What would settle the HOLD:** either of these.
  - Primary evidence that the web UI works in iPhone Safari: a vendor doc, issue or screenshot.
  - A stack-level A1 PASS through a screened iOS terminal app that attaches to CAO's tmux sessions, with tmux and a networking component also screened.

## Open questions
- **Does the web UI work acceptably in iPhone Safari?** This decides A1.
  - PARTIAL → PASS needs primary evidence: a vendor doc, issue or screenshot of phone use. Alternatively, the orchestrator may rule that source-level function plus documented remote access suffices.
  - Otherwise CAO's sessions need A1 from the 7.4 tmux path (a screened iOS terminal, tmux, and SSH into WSL2) or from another client.
- **Which reach path from the iPhone to WSL2?** This affects A1 (reach) and the stack's setup steps. Options:
  - Tailscale inside WSL2, with `cao-server --host <tailnet IP>` (the fleet bootstrap's pattern).
  - Windows Tailscale with WSL mirrored networking.
  - `tailscale serve` on Windows, proxying to `localhost:9889`.
  - Each needs `CAO_ALLOWED_HOSTS`, `CAO_WS_ALLOWED_CLIENTS` (or `*`) and `CAO_AUTH_LOCAL_TOKEN`; the proxy route may also need `CAO_FORWARDED_ALLOW_IPS`.
- **How will `cao-server` run unattended?** No service mode is documented. Starting it at boot and keeping the WSL2 distro alive is a stack setup step (C1 note; A1 persistence).
- **Deep-dive leads (not graded):**
  - **A2:** the web UI shows the TUI screen and a 32 KB output tail, not tool-call records. The audit trail will rest on the vendor TUIs (`claude --resume <id>`, which CAO's own `--resume` uses) or a viewer such as agentsview.
  - **A6b:** the CLIs run unmodified on the host, so their native transcripts should land in `~/.claude/projects` and `~/.codex/sessions`. Verify.
