## Summary
- Screen: HOLD (A3)
- Deep-dive (2026-10-19, deepdive-t3-code; v0.1.0 tag `81493efb`, cross-checked on main `ab6be13d`):
  - **ALWAYS gates, component level.** A1 PASS, A3 PASS (re-graded under 7.16b), A4 PASS, A5 PASS, A6 PASS, A7 PASS (sandbox clause not exercised), A8 PASS (first-class, both directions). A2 is PARTIAL at T3's defaults and PASS once text generation is set to a Claude instance.
  - **FAVOUR subtotals.** F1–F10 = 17/20. F11a–e = 10/10.
  - **Fact that most affects the stack.** T3 is a single component that launches and steers both native harnesses from the iPhone, and agents can create, monitor and resume cross-provider threads through its MCP. The open issues are policy and placement, not capability:
    - the Claude-token side read (policy risk);
    - the T3 Connect path through Cloudflare (avoid it; pair over Tailscale);
    - an always-on server belongs in WSL2, where Claude Desktop and ChatGPT desktop cannot see its sessions (F10 = 0).
- Re-grade (2026-10-19, brief 7.16b): A3 for the Claude path moves from FAIL to PASS, and F1 from FAIL to PARTIAL.
  - Why: the token read is a side read for non-inference calls that go only to api.anthropic.com. Inference runs in the user's installed `claude` on its own login.
  - Strict alternative (7.16b): Claude path A3 FAIL, component A3 PARTIAL.
- Correction (2026-10-19): the v0.1.0 doc `docs/user/activity-log.md` says "Raw command output and tool-result bodies are not shown". The v0.1.0 code does show them (web `V2ItemInspector.tsx`, mobile `thread-work-log.tsx`), and main corrected the doc on 2026-10-18. Release code wins (section 6).
- **Project health.** Healthy and active: MIT, 28.4k stars, v0.1.0 released 2026-10-15, 2,199 non-bot commits in the last 30 days. More than one maintainer: Julius Marminge wrote 41% of non-bot commits since 2026-04-23 and Theo Browne 14%.
- **Fit with the two modes.**
  - PC side: the Windows desktop app (.exe or winget) or the `t3` server in WSL2 (official Linux build). Windows has no background service, so an unattended always-on server belongs in WSL2 as a systemd user service.
  - Phone side: the App Store iPhone/iPad app 2.0.0 is V2-compatible and has iPad columns. It and app.t3.codes can list and read threads, reply, approve, answer questions, and start a task on a chosen provider and project, for Claude and Codex alike.
- **How the phone reaches the PC.**
  - Direct pairing over LAN, a Tailscale address or Tailscale HTTPS (`t3 serve --tailscale-serve`), or SSH.
  - Or T3 Connect: Clerk sign-in plus a T3-managed Cloudflare tunnel. Its relay brokers bootstrap credentials but "does not proxy" sessions.
  - No hosted part holds Claude or Codex credentials. app.t3.codes "connects directly to your server".
- **Harness paths.**
  - Claude: Claude Agent SDK `query()`, pointed at the user's installed `claude`, with the `claude_code` system-prompt preset (append only) and tools preset. A4 PASS.
  - Codex: the unmodified `codex app-server` under the user's own `codex login`. A3 and A4 PASS. An optional T3-managed "Connect with ChatGPT" runtime uses OpenAI's Sign in with ChatGPT plan sharing.
- **Why HOLD.**
  - On Windows, Linux and WSL2 hosts, the T3 server reads Claude's OAuth access token from `.credentials.json` itself. It sends the token to `api.anthropic.com/api/oauth/usage` on every provider check for subscription logins, and to `/reset_rate_limits` when the user redeems a reset. Both calls use a `claude-cli/<version> (external, cli)` user-agent. No opt-out was found.
  - Under 7.6, an Agent SDK tool that "collects … or relays tokens" fails A3. Anthropic says developers "may not collect, store, or intermediate Claude.ai credentials or session tokens". So the Claude path fails A3, and only Codex clears it: A3 is PARTIAL.
- **Caveat.** Since the v0.1.0 commit, the product is branded "T3 Code (Beta)" on desktop, web and mobile. The release notes call v0.1.0 stable.

### Harness integration (from source)
- **How it invokes `claude`.** Through the Claude Agent SDK `query()` (`@anthropic-ai/claude-agent-sdk` 0.3.276).
  - Binary: `pathToClaudeCodeExecutable` = the instance's `binaryPath` (default `claude` on PATH). The SDK's platform binaries are removed by pnpm overrides: "The SDK always receives the user's Claude executable" (P/pnpm-workspace.yaml#L203-L211; P/packages/contracts/src/settings.ts#L686-L700).
  - Session identity: `sessionId: nativeThreadId` on first run, `resume` thereafter (P/apps/server/src/orchestration-v2/Adapters/ClaudeAdapterV2.ts#L1122-L1124).
  - System prompt: `systemPrompt: {type:"preset", preset:"claude_code", append: runtime instructions + T3 orchestration instructions}`.
  - Tools: `tools` = the `claude_code` preset unless the read-only policy applies.
  - Other options: `includePartialMessages: true`; `canUseTool` routes approvals to T3's UI; `additionalDirectories` adds the cwd and the attachments dir; the user's launch args are parsed into `extraArgs` (P/…/ClaudeAdapterV2.ts#L1142-L1203).
  - Settings: `settingSources` is not set in turns, so all of the user's settings, CLAUDE.md and skills load (SDK sdk.d.ts L2140-L2150).
  - Config dir: `CLAUDE_CONFIG_DIR` is set only if the user configures `homePath` (providers-claude.md).
  - MCP: `mcpServers: {"t3-code": {type:"http", url, headers:{Authorization}}}` (P/…/ClaudeAdapterV2.ts#L1263-L1270).
  - Helper runs: `claude -p --output-format json --json-schema … --tools ""` (or read-only tools) `--disable-slash-commands --strict-mcp-config` (P/apps/server/src/textGeneration/ClaudeTextGeneration.ts#L205-L245).
- **How it invokes `codex`.** It spawns `binaryPath || "codex"` with `app-server` args. `CODEX_HOME` is set only if the user sets `homePath`, otherwise `~/.codex` (P/apps/server/src/orchestration-v2/Adapters/CodexAdapterV2.ts#L1536-L1553).
  - Per-thread config adds `tools.update_plan.enabled`, an MCP startup grace period, and `mcp_servers["t3-code"]`, layered over the user's `config.toml` (P/…/CodexAdapterV2.ts#L1311-L1360).
  - Threads use `thread/start`, `thread/resume` and `thread/fork`, and are not ephemeral.
  - The optional managed runtime downloads the official `openai/codex` release (SHA-256 pinned) into a T3-managed `CODEX_HOME` (screen row A4: Codex).
  - Helper runs: `codex exec --ephemeral --skip-git-repo-check -s read-only …` (P/apps/server/src/textGeneration/CodexTextGeneration.ts#L300-L310).
- **OAuth credentials.**
  - Claude: **reads**. On non-macOS hosts, `readAccessToken` reads `claudeAiOauth.accessToken` from `<config dir>/.credentials.json` (P/apps/server/src/provider/claudeResetCredits.ts#L150-L163). It runs on each Claude status check while the probe reports a subscription and usage is available (P/apps/server/src/provider/ClaudeProvider.ts#L673-L679), and again on a user-initiated reset (`consumeClaudeResetCredit`, P/…/claudeResetCredits.ts#L229-L250). Nothing is copied or persisted, and nothing is proxied except to `api.anthropic.com`.
  - Codex, default path: **none**. Account and limits come from app-server RPCs (P/apps/server/src/provider/CodexProvider.ts#L495, #L517). The usage meter reads `$CODEX_HOME/sessions` transcripts, not credentials (M/apps/server/src/provider/Drivers/codexUsage.ts#L210-L231).
  - Codex, optional "Connect with ChatGPT": T3 runs Sign in with ChatGPT and **holds** the plan-usage tokens. It passes them to the official binary as `ACCESS_TOKEN` (screen row A3: Codex) and can export them between environments (`ChatGptTransferredProfile`). Avoid this path; use `codex login`.
- **Credential-handling policy risk (7.16b).**
  - Anthropic's legal page says: "Anthropic does not permit third-party developers to offer Claude.ai login into their own applications, or to route requests through Free, Pro, or Max plan credentials on behalf of their users. Moreover, developers may not collect, store, or intermediate Claude.ai credentials or session tokens" (https://code.claude.com/docs/en/legal-and-compliance, undated, retrieved 2026-10-19).
  - What T3 does on Windows, Linux and WSL2:
    - its server process reads the user's Claude OAuth access token from Claude Code's credentials file;
    - it calls `GET https://api.anthropic.com/api/oauth/usage?cedar_ember=1&skip_spend=1` and, on user action, `POST /api/organizations/<org>/reset_rate_limits`;
    - it presents itself as the Claude CLI: `user-agent: claude-cli/<installed version> (external, cli)` and `anthropic-beta: oauth-2025-04-20`. That is client impersonation.
  - No setting disables this short of disabling the Claude provider (P/apps/server/src/provider/ClaudeProvider.ts#L523). macOS hosts skip it (keychain).
  - Untested mitigation: authenticate Claude only via `CLAUDE_CODE_OAUTH_TOKEN` (`claude setup-token`) so no `.credentials.json` exists. `readAccessToken` then returns nothing; the reset feature disappears and F1 stays PARTIAL as an injected token.
- **Transcript locations it relies on or produces.**
  - Claude: `~/.claude/projects/<encoded cwd>/<sessionId>.jsonl`, or under a custom `CLAUDE_CONFIG_DIR`. Title helpers run in temp dirs, so their transcripts sit under temp-path project folders.
  - Codex: `~/.codex/sessions/…` rollouts, or under a custom `CODEX_HOME` or managed home. Helpers write none (`--ephemeral`).
  - T3's own durable thread state: `~/.t3/userdata` (P/docs/user/background-service.md).

  - Run `t3` in WSL2 as a systemd user service (`t3 service install`), with the Claude and Codex CLIs installed and logged in inside the distro.
  - Pair the phone directly over Tailscale (`t3 serve --tailscale-serve`, or the tailnet IP), which is WireGuard end to end.
  - Use the Windows desktop app as a client of that environment, or let it manage the WSL distro (it must stay open).
  - Avoid T3 Connect if privacy matters. After bootstrap, "clients send application traffic through the environment's tunnel hostname", a T3-managed Cloudflare tunnel to "a validated loopback HTTP origin", so thread content transits Cloudflare's edge. The relay is "a trusted broker" holding mint-signing authority (P/docs/internals/t3-connect.md#L1-L10, #L35-L60).

  - Networking for direct pairing (tailwind/Tailscale, pending screen).
  - A transcript viewer for long outputs and helper runs (vendor TUIs as givens, or agentview-b).
  - Raise Claude's `cleanupPeriodDays`.
  - Set T3's text generation to a Claude instance (A2).
  - F9 would need a container runtime that T3 can launch sessions into. T3 has none, so a Docker component would sit beside T3, not under it.
- **Conflicts and caveats.**
  - **F10 vs always-on.** A WSL2-hosted T3 writes WSL2-side stores that Claude Desktop doesn't list. The Codex app is unverified.
  - **Two credential stores.** Desktop apps on Windows and T3 in WSL2 keep separate logins and transcript stores.
  - **Concurrent use.** Continuing a T3 session in the vendor TUI works (F5), but T3's UI won't show those turns.
  - **Beta label.** The product is labelled "T3 Code (Beta)". That is a caveat only under 7.16a, since v0.1.0 is the stable Latest release.
  - **Version lock.** The server and mobile app must both be V2.
