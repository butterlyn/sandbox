## Summary
- Screen: HOLD (A3)
- **Project health.** Healthy and active: MIT, 28.4k stars, v0.1.0 released 2026-10-15, 2,199 non-bot commits in the last 30 days. More than one maintainer: Julius Marminge wrote 41% of non-bot commits since 2026-04-23 and Theo Browne 14%.
- **Fit with the two modes.**
  - PC side: the Windows desktop app (.exe or winget) or the `t3` server in WSL2 (official Linux build). Windows has no background service, so an unattended always-on server belongs in WSL2 as a systemd user service.
  - Phone side: the App Store iPhone/iPad app 2.0.0 is V2-compatible and has iPad columns. It and app.t3.codes can list and read threads, reply, approve, answer questions, and start a task on a chosen provider and project, for Claude and Codex alike.
- **How the phone reaches the PC.**
  - Direct pairing over LAN, a Tailscale address or Tailscale HTTPS (`t3 serve --tailscale-serve`), or SSH.
  - Or T3 Connect: Clerk sign-in plus a T3-managed Cloudflare tunnel. Its relay brokers bootstrap credentials but "does not proxy" sessions.
  - No hosted part holds Claude or Codex credentials. app.t3.codes "connects directly to your server".
- **Harness paths.**
  - Claude: Claude Agent SDK `query()`, pointed at the user's installed `claude`, with the `claude_code` system-prompt preset (append only) and tools preset. A4 PASS.
  - Codex: the unmodified `codex app-server` under the user's own `codex login`. A3 and A4 PASS. An optional T3-managed "Connect with ChatGPT" runtime uses OpenAI's Sign in with ChatGPT plan sharing.
- **Why HOLD.**
  - On Windows, Linux and WSL2 hosts, the T3 server reads Claude's OAuth access token from `.credentials.json` itself. It sends the token to `api.anthropic.com/api/oauth/usage` on every provider check for subscription logins, and to `/reset_rate_limits` when the user redeems a reset. Both calls use a `claude-cli/<version> (external, cli)` user-agent. No opt-out was found.
  - Under 7.6, an Agent SDK tool that "collects … or relays tokens" fails A3. Anthropic says developers "may not collect, store, or intermediate Claude.ai credentials or session tokens". So the Claude path fails A3, and only Codex clears it: A3 is PARTIAL.
- **Caveat.** Since the v0.1.0 commit, the product is branded "T3 Code (Beta)" on desktop, web and mobile. The release notes call v0.1.0 stable.

## Open questions
- **Does the reset-credit token read count as "collects … or relays tokens" under 7.6?**
  - Facts: the token stays on the user's machine, goes only to Anthropic, and is never used for inference.
  - If the orchestrator rules that it does not count, then A3: Claude becomes PASS, component A3 becomes PASS, and the outcome becomes SCREEN PASS.
  - Otherwise T3 cannot be the stack's Claude path for A3. It can still be the Codex path and the iPhone client.
- **Can configuration avoid the read?**
  - No opt-out setting exists in v0.1.0 or on `main` `9077e818`.
  - Untested workaround: authenticate Claude only with `CLAUDE_CODE_OAUTH_TOKEN` (from `claude setup-token`), set in the WSL2 service environment and not in T3's provider settings, so that no `.credentials.json` exists. `readAccessToken` returns nothing when the file is missing (P/apps/server/src/provider/claudeResetCredits.ts#L138-L156).
  - If that works, Claude would sit on the injected-token row: A3 PASS, F1 PARTIAL. It needs testing that T3's capability probe and turns work this way. This changes A3 (Claude) and F1.
- **Does the server stay up unattended in WSL2?**
  - T3 documents a systemd user service with lingering on Linux.
  - Whether WSL2 keeps the distro running with no Windows-side session depends on WSL configuration, which T3's docs don't cover.
  - This changes the C1 unattended note and the stack's always-on design, not the C1 verdict.
- **Is T3 Connect encrypted end to end?**
  - Tunnels terminate on "a validated loopback HTTP origin". The docs claim no end-to-end encryption between phone and PC, and the relay is a self-described "trusted broker".
  - The managed ChatGPT path can also export and import ChatGPT tokens between environments (`ChatGptTransferredProfile`, P/packages/contracts/src/providerSetup.ts). Over T3 Connect, those tokens would cross the tunnel.
  - A3 is unaffected while the stack uses direct Tailscale pairing and the installed `codex login`. This would matter only for a stack that relies on T3 Connect or on the managed ChatGPT path (7.6 relay note).
- **Does the product-wide "Beta" label matter?**
  - The v0.1.0 tag commit renamed the product "T3 Code (Alpha)" → "T3 Code (Beta)" on desktop, web and mobile, while the release calls V2 "stable".
  - If the orchestrator treats this as "beta only" under section 5, every PASS above would become PARTIAL.
