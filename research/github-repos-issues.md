## Summary
- Screen: PASS
- **Maintenance (N2, N3).** GitHub, Inc. is an organisation with "a workforce of 3,000 + talented Hubbers". Its leadership page is headed by Microsoft's Executive Vice President for CoreAI.
  - GitHub Mobile ships weekly; the latest is 1.281.0 (2026-10-15).
  - The changelog has 245 entries in the last 90 days, including PR, issue and Projects features.
  - No in-scope surface carries a deprecation notice. Projects (classic) was sunset in 2024; its successor, Projects, is the surface in scope.
  - N1 does not apply (closed source).
- **Both modes (C1).**
  - iPhone and iPad: a universal App Store app (iOS/iPadOS 17.0+).
  - PC: github.com in a supported browser, and git natively (Git for Windows 2.56.0(2), 2026-10-05) or in WSL2 (preinstalled in most distros).
  - Nothing runs unattended on the PC. Files sync only when an agent, a script or the user runs `git push` or `git fetch`.
- **A1, A3, A4: N/A (layer).** It launches no Claude Code or Codex session. GitHub's own agent surfaces are out of scope: Actions runners, Copilot, and the partner Claude and Codex agents in GitHub Mobile, which are billed to Copilot.
- **What it adds to a stack.**
  - A5: committed and pushed state only, which 7.2 grades PARTIAL.
  - A7: Claude Code cloud and Codex cloud both hand work to and from the PC through GitHub branches and PRs.
  - F4: iPad layout with a sidebar, plus keyboard and pointer support.
  - F7: markdown, images and SVG render in the app.
  - F8: attachment types and size limits are documented.
- **Main caveats.**
  - No documented API lets an agent download issue attachments from a private repo.
  - git, `gh` and the GitHub MCP server are not screened (see Open questions).

## Open questions
- **Is git a given or a component?** The PC side of C1, and every A5/A7 use of GitHub, relies on git. Natively that means Git for Windows with Git Credential Manager; in WSL2, the distro's git.
  - 7.12's list of givens does not name git.
  - Claude Code's setup page calls Git for Windows "optional" and says "WSL setups do not need Git for Windows" (https://code.claude.com/docs/en/setup, undated, retrieved 2026-10-19). So git is not a hard prerequisite of a given harness.
  - If git is a component, git/git, git-for-windows/git and Git Credential Manager (linked by Microsoft as GitCredentialManager/git-credential-manager) each need an N1–N3 screen before a stack leans on GitHub.
  - Not run here. It changes stack composition (7.12), not this screen's outcome.
- **Agent-side GitHub tooling is unscreened.** Agents would reach issues and PRs through `gh` (cli/cli) or the GitHub MCP server. Both are open-source components outside this candidate.
  - `gh`: latest tag v2.102.0, released 2026-09-30 (release page "30 Sep"; tagged commit 2026-09-29T20:18-06:00). `--attach` arrived in v2.99.0 (2026-09-01).
  - This matters for F8 (M2→M1 via `--attach`) and for any stack that uses issues as its task queue. The REST and GraphQL APIs themselves are part of GitHub.com.
- **Can an agent download attachments from a private repo?** GitHub documents no API for fetching `user-attachments` in a private repo.
  - Third-party leads, which are not evidence, report that token requests return 404, and suggest scraping signed URLs from the rendered issue HTML.
  - This would move the attachment route for F8 (M1→M2), and any A7 use of attachments, from UNKNOWN to PASS or FAIL.
  - Settled by a GitHub doc, or by a test with the user's token.
- **iOS app: attachment types and PDF viewing.**
  - No primary source says the iOS app can attach non-media files (PDF, ZIP, …) to comments. The only lead is an Android 1.112.0 note on APKMirror (2023).
  - In-app PDF rendering was last documented in 2020 (v1.2).
  - These affect F7 and F8 detail. A release note or a device test would settle them.
- **Uploading to a repo from iPhone Safari.** GitHub documents "Add file > Upload files" for "a browser" without naming iOS. Safari's file picker is an Apple given that still needs an Apple source. This affects F8 (M1→M2 into the repository).
