# Warp

- Slug: warp
- Canonical: https://github.com/warpdotdev/warp (client source), https://www.warp.dev, https://docs.warp.dev; Oz web app https://oz.warp.dev (the docs now say "Automation Platform (formerly Oz)")
- Layer(s): client/UI (W1); orchestrator and runtime/sandbox (W2, Oz cloud)
- Open source: yes, for the client: AGPL-3.0, with the `warpui_core`/`warpui` UI crates under MIT. The Oz cloud service and web app are closed source.
- Latest release checked: v0.2026.10.14.08.27, 2026-10-15, https://docs.warp.dev/changelog/2026/ (Warp ships through its changelog. The GitHub Releases page lags: its last "Latest" is v0.2026.06.03.09.49.stable_00 from 2026-06-03.)
- Checked: 2026-10-19 by screen-warp

## Summary
- Screen W1 (Warp client running the `claude` and `codex` CLIs, plus Remote Control): **SCREEN HOLD (A1)**
- Screen W2 (Oz / Automation Platform cloud harnesses for Claude Code and Codex): **SCREEN FAIL at A3**
- Deep-dive (W1 only, by deepdive-warp, 2026-10-19):
  - ALWAYS gates: A2, A3 and A4 PASS; A6, A7 and A8 PASS (workaround); A1 and A5 PARTIAL.
  - FAVOUR: F1–F10 = 9/20 with Windows-native shells (7/20 with WSL2 shells, where F10 drops to 0); F11a–e = 1/10.
  - Role: an optional PC terminal for the native TUIs. It adds no ALWAYS-gate coverage that another component doesn't already supply.
  - The shell-share workaround for A1 does not hold up: shares expire about a week after creation, and renewal is only wired into the Oz driver, so the user must re-share from the PC every week.
- Precision (2026-10-19, deepdive-warp): the Remote Control auto-stop applies to shares started from the CLI-agent toolbar, which use scrollback type None. A plain "Share current session" from the command palette is not auto-stopped when an agent exits.
- Warp clears N1–N3 on its client repo:
  - 65.5k stars;
  - 362 human commits to `master` in the last 90 days;
  - weekly releases;
  - two different humans merged other people's PRs in the last week.
- W1 is clean on harness and login. In a Warp pane, on native Windows or in a WSL2 shell, the user runs the unmodified `claude` and `codex` under their own subscription logins. Warp only installs notification plugins; I found no credential handling in its CLI-agent integration code.
- W1's phone path is Remote Control: a sign-in-gated web link for one running session, carried through Warp's servers.
  - What works: the link shows thinking, tool calls and terminal output, and with edit access it takes input and approvals.
  - What does not: the phone cannot list sessions or start one. Each link is created on the PC and stops automatically when that agent exits. Shares expire after about a week, and Warp staff say the Free plan limits them.
  - Result: A1 PARTIAL, so W1 needs a partner component for listing and launching sessions from the phone.
- W2 fails A3 for both harnesses. Oz accepts only Anthropic API keys (direct or via Bedrock) and OpenAI API keys, stored as Warp secrets, and says "A ChatGPT subscription … does not include API access". There is no subscription path, so the 7.6 "third-party-hosted" row never comes into play. Otherwise Oz runs the unmodified CLIs (A4 PASS), and its web app works on a phone.
- Caveat for any Warp stack:
  - Remote Control and Session Sharing upload scrollback to Warp's servers and keep it for about a week, without secret redaction.
  - The Warp GUI must stay open on the PC. It is not a service.

## Open questions
- **W1 A1(i), session list.** Does any Warp web surface (for example the app.warp.dev home) list a user's active shared or Remote Control sessions on a phone? None is documented. If one exists, the listing half of A1(i) passes.
- **W1 A1(i)/(iii), shell-share workaround.** The idea: a generic "Share current session" of a plain shell pane, not Remote Control (which auto-stops when the agent exits), kept open with edit access. From iOS Safari the user would then run `cd <repo> && claude` or `codex`, and use `claude --resume` or `codex resume` as session lists.
  - What must be shown: that it works, and that the share can be kept alive beyond the one-week expiry without going back to the PC.
  - Pointer: the source has `extend_session_retention` → `UpstreamMessage::ExtendSessionRetention` (https://github.com/warpdotdev/warp/blob/ae60375ef1d3895908756878fe4a07cbe703ce1a/app/src/terminal/shared_session/sharer/network.rs#L1936-L1941).
  - If shown, A1 could become `PASS (workaround)` under the 7.4 generic-terminal rule. Settled by: a primary doc, or a hands-on test.
- **W1 plan cost.** Which paid Warp plan lifts the Free-plan limit on shared and Remote Control sessions? Staff said about 3 lifetime shares on Free, a number "no longer advertise[d]" (#14661). Is there a cap on concurrent shares? This affects whether the A1 path is viable, not the verdict.
- **W1 usability.** Open bug #13474: on Windows with WSL2, the mobile viewer reflows the local Codex TUI. This is a caveat for A1 and F4.
- **W2 A1(ii).** Can Claude Code and Codex harness runs be continued or steered from the Oz web app on a phone? It is moot while A3 fails.
- **W2 A3, subscription path.** Will Warp add subscription sign-in for harness runs?
  - Anthropic's legal page (dated 2026-10-05) now says its terms do not "prevent an end user from signing in to the unmodified Claude Code binary with their own Claude subscription, including where a platform hosts Claude Code" (https://code.claude.com/docs/en/legal-and-compliance). If Warp documented such a path, Claude Code would move to the 7.6 third-party-hosted row: PARTIAL unless an approved arrangement is documented. Codex has no such Warp path.
  - Self-hosted Oz workers run the CLIs on the user's own host, and the Codex driver preserves an existing login ("so we don't clobber an existing login", codex.rs#L710-L712). But self-hosting "requires an Enterprise plan" (https://docs.warp.dev/factories/self-hosting/, 2026-10-18), and subscription use there is undocumented. Out of reach for one user.
- **Out of scope, flag for Stage 4.** Since 2026.09.23, Warp Agent can "sign in with ChatGPT to use your ChatGPT plan". That is a non-native harness on a ChatGPT plan (7.6: A4 FAIL). A Warp stack must not count it as Codex.
