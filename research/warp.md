# Warp

- Slug: warp
- Canonical: https://github.com/warpdotdev/warp (client source), https://www.warp.dev, https://docs.warp.dev; Oz web app https://oz.warp.dev (the docs now say "Automation Platform (formerly Oz)")
- Layer(s): client/UI (W1); orchestrator and runtime/sandbox (W2, Oz cloud)
- Open source: yes, for the client: AGPL-3.0, with the `warpui_core`/`warpui` UI crates under MIT. The Oz cloud service and web app are closed source.
- Latest release checked: v0.2026.10.14.08.27, 2026-10-15, https://docs.warp.dev/changelog/2026/ (Warp ships through its changelog. The GitHub Releases page lags: its last "Latest" is v0.2026.06.03.09.49.stable_00 from 2026-06-03.)
- Checked: 2026-10-19 by screen-warp

## Summary
- Screen W1 (Warp client running the `claude` and `codex` CLIs, plus Remote Control): **SCREEN HOLD (A1)**
- Screen W2 (Oz / Automation Platform cloud harnesses for Claude Code and Codex): **SCREEN FAIL at A3**
- Deep-dive (W1 only, by deepdive-warp, 2026-10-19):
  - ALWAYS gates: A2, A3 and A4 PASS; A6, A7 and A8 PASS (workaround); A1 and A5 PARTIAL.
  - FAVOUR: F1–F10 = 9/20 with Windows-native shells (7/20 with WSL2 shells, where F10 drops to 0); F11a–e = 1/10.
  - Role: an optional PC terminal for the native TUIs. It adds no ALWAYS-gate coverage that another component doesn't already supply.
  - The shell-share workaround for A1 does not hold up: shares expire about a week after creation, and renewal is only wired into the Oz driver, so the user must re-share from the PC every week.
- Precision (2026-10-19, deepdive-warp): the Remote Control auto-stop applies to shares started from the CLI-agent toolbar, which use scrollback type None. A plain "Share current session" from the command palette is not auto-stopped when an agent exits.
- Warp clears N1–N3 on its client repo:
  - 65.5k stars;
  - 362 human commits to `master` in the last 90 days;
  - weekly releases;
  - two different humans merged other people's PRs in the last week.
- W1 is clean on harness and login. In a Warp pane, on native Windows or in a WSL2 shell, the user runs the unmodified `claude` and `codex` under their own subscription logins. Warp only installs notification plugins; I found no credential handling in its CLI-agent integration code.
- W1's phone path is Remote Control: a sign-in-gated web link for one running session, carried through Warp's servers.
  - What works: the link shows thinking, tool calls and terminal output, and with edit access it takes input and approvals.
  - What does not: the phone cannot list sessions or start one. Each link is created on the PC and stops automatically when that agent exits. Shares expire after about a week, and Warp staff say the Free plan limits them.
  - Result: A1 PARTIAL, so W1 needs a partner component for listing and launching sessions from the phone.
- W2 fails A3 for both harnesses. Oz accepts only Anthropic API keys (direct or via Bedrock) and OpenAI API keys, stored as Warp secrets, and says "A ChatGPT subscription … does not include API access". There is no subscription path, so the 7.6 "third-party-hosted" row never comes into play. Otherwise Oz runs the unmodified CLIs (A4 PASS), and its web app works on a phone.
- Caveat for any Warp stack:
  - Remote Control and Session Sharing upload scrollback to Warp's servers and keep it for about a week, without secret redaction.
  - The Warp GUI must stay open on the PC. It is not a service.

### Harness integration (from source)
- **How it invokes `claude`:** in W1 it does not launch the CLI itself. The user, or a Tab Config, types `claude` in a pane. Warp spots the agent from the command's first word (basename `claude`, aliases resolved) and shows its toolbelt.
  - Sources: [cli_agent.rs#L215-L219](https://github.com/warpdotdev/warp/blob/ae60375ef1d3895908756878fe4a07cbe703ce1a/app/src/terminal/cli_agent.rs#L215-L219) and [#L459-L512](https://github.com/warpdotdev/warp/blob/ae60375ef1d3895908756878fe4a07cbe703ce1a/app/src/terminal/cli_agent.rs#L459-L512).
  - The plugin it offers is installed with `claude plugin marketplace add warpdotdev/claude-code-warp` then `claude plugin install warp@claude-code-warp`, run in the user's login shell ([claude.rs#L97-L108](https://github.com/warpdotdev/warp/blob/ae60375ef1d3895908756878fe4a07cbe703ce1a/app/src/terminal/cli_agent_sessions/plugin_manager/claude.rs#L97-L108), [mod.rs#L96-L107](https://github.com/warpdotdev/warp/blob/ae60375ef1d3895908756878fe4a07cbe703ce1a/app/src/terminal/cli_agent_sessions/plugin_manager/mod.rs#L96-L107)).
  - Its hooks (SessionStart, Stop, Notification, PermissionRequest, UserPromptSubmit, PostToolUse, StopFailure) only emit OSC 777 notifications.
- **How it invokes `codex`:** the same detection. The plugin is installed with `codex plugin marketplace add warpdotdev/codex-warp` then `codex plugin add warp@codex-warp` ([codex.rs#L153-L163](https://github.com/warpdotdev/warp/blob/ae60375ef1d3895908756878fe4a07cbe703ce1a/app/src/terminal/cli_agent_sessions/plugin_manager/codex.rs#L153-L163)). - **Transcripts:**
  - Native stores only: `~/.claude/projects`, and `$CODEX_HOME/sessions` (or `%USERPROFILE%\.codex` on native Windows).

### Stack fit
- **Layers covered:** client/UI on the PC (the terminal for the native TUIs), plus a per-session phone mirror. It adds no ALWAYS-gate coverage that the shortlisted components lack.
- **Best placement:** Windows-native shells (PowerShell) with repos on `C:\`. That matches the claude-desktop + chatgpt-desktop-codex topology: the file tree and code review work, and F10 = 2. In WSL2 shells the file tree and code review are unavailable and F10 = 0, though notifications work (changelog 2026.05.14).
- **Partners needed:**
  - A1 listing and starting: the Claude iOS app via `claude remote-control` server mode, ChatGPT iOS remote connections for Codex, or an orchestrator's app (Orca, T3 Code).
  - A5/F7/F8: Tailscale + Windows SMB → iOS Files.
  - F6: Tailscale Serve.
  - Full history on the phone: agentsview behind `require_auth`.
- **Redundancy:** for Claude, the Claude iOS app's Remote Control already covers more of A1 than a Warp share. Warp's value is PC-side UX: notifications, vertical tabs, rich input, and code-review comments sent to the agent.
- **Privacy and cost:**
  - Shared scrollback sits on Warp's servers for about a week with no secret redaction, so anything an agent prints (env vars, tokens) is exposed to viewers.
  - Viewers must sign in to a Warp account.
  - Free plan: "I believe it was 3 total lifetime shared sessions" (staff, hedged). Paid plans advertise "Unlimited Session Sharing".
- **Conflicts:**
  - Warp Agent's "sign in with ChatGPT" is a non-native harness (7.6) and must not be counted as Codex.
  - The Warp GUI must stay open; it is not a service.
  - A Remote Control share ends when its CLI agent exits, so every agent restart needs a new share, created at the PC.
