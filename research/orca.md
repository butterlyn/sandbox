## Summary
- Screen: SCREEN HOLD (A1)
- N1–N3 pass easily. The repo is active, MIT-licensed and not archived. It shows 96.8k stars. Four humans each wrote ≥10% of commits in the window. v1.4.229 shipped on 2026-10-17, and there were about 7,900 non-bot commits in the last 90 days.
- C1 passes. A native Windows installer ships, and Windows terminals and Codex can run inside WSL. Agent PTYs live in a background daemon that survives quitting the app. The phone, however, connects only while the desktop app (or the headless `orca serve`, which is beta) is running on the PC.
- On function, A1 is met for both Claude Code and Codex. The App Store app lists workspaces and agents, mirrors the live terminal and reads its scrollback. It can reply, answer prompts and approvals, and create a workspace or new tab with a chosen agent. It connects through Orca Relay (vendor-hosted, end-to-end encrypted) or directly over LAN or Tailscale. A1 is held at PARTIAL only because the vendor docs say "The mobile companion is in beta" (section 5: "preview/beta only").
- A3 and A4 pass in the default terminal mode. Orca types the bare `claude` / `codex` command into an interactive shell in a node-pty PTY, and each CLI uses its own login. The experimental Chat UI mode is off by default. It drives Claude through the Claude Agent SDK, which runs the user's installed `claude` with the `claude_code` preset, and Codex through `codex app-server`. Under Anthropic's current Agent SDK note, that Claude path is not a PASS, so the stack should keep Chat UI off.
- Credential caveat: Orca reads OAuth tokens to poll vendor usage endpoints. The Claude token comes from the keychain or `.credentials.json`, and the Codex token from `auth.json`. Orca also copies Codex `auth.json` between `~/.codex` and its own runtime `CODEX_HOME`. This is not an agent loop or proxy, so A3 is unaffected under 7.6, but F1 cannot be PASS. The docs say "No API calls, no extra auth", and the source contradicts this.

## Open questions
- Does a public App Store app that the vendor's docs call "beta" count as "preview/beta only"? It is a production listing, not TestFlight, but `mobile.mdx` says "The mobile companion is in beta". A1 moves from PARTIAL to PASS, and Screen from HOLD to PASS, if the orchestrator rules it is not beta-only or the vendor drops the label. Nothing else in the screen is outstanding.
- The App Store description says "same Wi-Fi as your desktop" and "local network only", while the latest docs and source describe Orca Relay and Tailscale; the mobile transport has relay and E2EE modules. A deep-dive should confirm on the shipping iOS 0.0.57 build that Relay pairing reaches a Windows host off-LAN. This would change A1 (reach) and the C1 phone note. Issue #30191 (open, 2026-10-18, `os:Windows`) reports the mobile view flickering while a Windows host's agent is running: https://github.com/stablyai/orca/issues/30191
- Windows specifics are unconfirmed. The daemon is documented to survive "Cmd-Q", but it is not confirmed for Windows quit or close. Whether `orca serve` runs natively on Windows or only on Linux/WSL2 is also open. `minimizeToTrayOnClose` exists in source but not in the docs. These affect the C1 unattended note and A1 (persist), since the phone needs the desktop runtime up.
- How should the experimental Chat UI mode be graded under A3? It runs Claude through the Agent SDK on the user's subscription login, and Orca's "Add account" runs `claude auth login --claudeai`. Anthropic's Agent SDK note bars unapproved third-party products from offering claude.ai login or rate limits, and whether Orca has approval is unknown. If the stack needs Chat UI (mobile Chat UI cards, a rendered A2 trail), A3 becomes FAIL or UNKNOWN for that mode. The source also mentions an older "terminal-backed chat" fallback. The deep-dive should check whether mobile Chat UI works over plain PTY sessions with `experimentalNativeChat` off (affects A2, F11e).
- Is credential touching material under A3? Orca reads tokens to poll usage endpoints, spends Codex reset credits through `chatgpt.com/backend-api`, and mirrors Codex `auth.json` into its runtime `CODEX_HOME`. It is not an agent loop or proxy, so this file grades A3 PASS. If the orchestrator rules it material, A3 becomes PARTIAL. F1 is at most PARTIAL either way.
- Is the star count genuine? 96.8k stars against 152 watchers is an unusual ratio. N1 (≥1,000) is unaffected. F2 (>5,000) is very likely unaffected too, given 6.2k forks and 465 commit-author identities in six months.
