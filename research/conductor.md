## Summary
- Screen: FAIL at C1
- **Why it fails.** Conductor is a closed-source macOS desktop app. Its install page says "Conductor is not available for Windows or Linux yet". The vendor's updater feed and web download page serve only macOS DMGs (Apple silicon and Intel); the Linux and Windows platform keys return "Unknown update platform" or 404. Under 7.9, macOS-only is FAIL, and the user's setup has no Mac.
- **No other route reaches the Windows PC:**
  - There is no Windows or browser UI for workspaces. Web workspace links only hand off to the Mac app through a `conductor://` deep link.
  - There is no remote-host or self-hosted runner ("Can I use my own cloud machines…? Not yet").
  - Conductor Cloud runs agents in Conductor-managed Vercel sandboxes and is set up from the Mac app. From Windows it is reachable only through a beta HTTP API and a hosted MCP server, which is neither an app nor a browser UI.
- **The iOS app does not change C1.** The new app (1.0.8, 2026-10-15, listed "Only for iPhone") "works with cloud workspaces", so the phone side exists, but the PC-side component is still macOS-only.
- **Earlier checks:**
  - N3 PASS: 24 changelog entries since 2026-07-21, and no sunset notice.
  - N1 N/A: closed source.
  - N2 PASS: the site names the vendor (Melty Labs, Inc. / Melty, Inc., YC S24, San Francisco) and seven team members, and two co-founders sign the Series A post. This corrects the Stage 1 lead that the vendor is not named on the site. The homepage doesn't name it, but the privacy notice, terms, footer and brand kit all do.
- **Not screened:** A1 and A3/A4, because 7.11 stops at the first hard fail. Ungraded observations for any re-screen are under Open questions.

## Open questions
- **Will a Windows or Linux build ship?** Either would reopen C1 (7.9), and then A1 and A3/A4. For WSL2, a Linux build would need to be official, not labelled beta or experimental, and usable under WSLg. Leads so far:
  - The install page has a waitlist ("Sign up here and we will let you know when it is ready").
  - The Series A post (2026-03-30) says Conductor "will become the platform for managing huge AI organizations, available everywhere from your phone to your VPC".
  - Lead only: the deep-link channel table in the app.conductor.build bundle includes `alpha-chromium` → `conductor-alpha-chromium`. This may hint at a Chromium-based alpha build, but no non-macOS artefact is published.
- **What will the self-hosted cloud offer?** The Cloud FAQ says "we are building a self-hosted cloud offering" (Enterprise). If it lets agents run on a user-owned Linux host such as WSL2, with the iOS app as the phone client, C1 would need re-screening.
- **Can Cloud be set up without a Mac?** The docs describe setup only from the Mac app. The web bundle has routes such as `/create-org`, `/cloud-collab-onboarding`, `/setup/$organizationSlug` and `/mobile-signin`, but no no-Mac flow is documented. Even if web setup works, C1 would be PARTIAL at best:
  - Windows would reach cloud workspaces only through the beta API/MCP, which is neither app nor browser.
  - Agents would run in Conductor-managed Vercel sandboxes using "a personal subscription token or API key" uploaded to Conductor (Set up cloud). That is the 7.6 "third-party-hosted service" row: A3 PARTIAL unless an approved arrangement with Anthropic/OpenAI is documented.
- **Ungraded observations, in case Conductor is ever re-screened (A1, A3/A4):**
  - **A1.** The iOS app works with cloud workspaces only, so per its release note local Mac workspaces are not reachable from the phone. The docs do not say whether it can start a session and choose the harness and repo. The App Store text says only "control your agents from your phone, keep them running, review code, see PR status, merge your changes and more". The listing is iPhone-only, so it runs scaled on iPad (relevant to F4).
  - **A3/A4, Claude path.** The blog says "Conductor uses native Claude Code, but we do so through the Claude Agent SDK" (https://www.conductor.build/blog/claude-subscription-update, 2026-06-15).
    - The app bundles its own Claude Code and Codex ("Do not update or modify them"), and "Conductor injects system prompts that explain to the agent that it's running inside Conductor" (docs FAQ).
    - That puts it on the 7.6 Agent SDK row. The deciding question is whether those prompts are appended to Claude Code's default prompt or replace it.
    - The same post says Anthropic's 2026-05-13 subscription changes for Agent SDK use in third-party tools were "delayed indefinitely" on 2026-06-15. A3 would therefore need the current Anthropic primary docs.
  - **A3/A4, Codex path.** Conductor offers its own "Sign in with ChatGPT" ("We're excited to be partnering with OpenAI", https://www.conductor.build/blog/sign-in-with-chatgpt, 2026-09-29) alongside `codex login` (install page). That falls under the 7.6 row "`codex app-server` with externally managed ChatGPT tokens" plus 7.16c, and would need OpenAI-documented consent.
