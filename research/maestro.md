**Credential-handling policy risk (7.16b), Codex path only.**
- **What Maestro does.** `codex-auth.ts` reads `CODEX_HOME/auth.json`: the `access_token`, `account_id`, and an email decoded from `id_token` for labels. It sends `Authorization: Bearer …` plus `ChatGPT-Account-Id` to chatgpt.com's undocumented `backend-api/wham/usage` and `wham/rate-limit-reset-credits` endpoints. The POST to the second spends a reset credit, either on a manual "Reset now" or through the per-agent auto-reset, which is off by default.
- **What stays clean.**
  - Tokens go only to chatgpt.com and never to Maestro's servers.
  - No client impersonation was found: no user-agent or `originator` header.

  - Vendor-native transcripts in the user's own `~/.claude/projects` and `$CODEX_HOME/sessions` (both persisted).
  - Maestro's own tab logs and History entries.
  - `maestro-cli session show` reads the desktop's tab log over WebSocket ("There is no on-disk fallback").
- **Security notes:**
  - Default agents run with all checks off: Claude Full Access is `--dangerously-skip-permissions`, and Codex always runs with approvals and sandbox bypassed (`--dangerously-bypass-approvals-and-sandbox`, "full system access, required by Maestro"). Agents can also drive Maestro itself through `maestro-cli`, e.g. creating or removing agents and dispatching work.
  - The phone link is plain HTTP plus a URL token (LAN). Over Tailscale it rides WireGuard. Optional Web Login adds per-browser passwords.

### Stack fit
- **Layers covered:** orchestrator and client/UI, with a phone webapp, for **both** harnesses.
- **What Maestro covers on its own:** iPhone reach for listing, reading, messaging and starting sessions (A1 (i)/(iii), Codex (ii)); A5 workspace browsing; A6–A8 first-class delegation; F7; most of F11.
- **Recommended topology on the user's PC:**
  - Maestro v1.0.0 Windows installer, with the Windows-native `claude` and `codex` CLIs and repos on `C:\`. This is the same Windows-native placement that research/claude-desktop.md and research/chatgpt-desktop-codex.md recommend, so all three share `%USERPROFILE%\.claude` and `%USERPROFILE%\.codex`.
  - Settings: turn on LIVE web-UI auto-start, persistent web link and a custom port; turn on "Show tool calls in responses"; raise Claude `cleanupPeriodDays`; keep `ANTHROPIC_API_KEY` unset.
  - Add the `maestro-cli.cmd` shim so agents can call the CLI.
  - The desktop app must stay running in a signed-in Windows session. It has no service mode, and agents are its child processes.
- **WSL2 is possible but second-best.** Agents must use SSH-remote mode, which allows no Standard permission mode and needs `maestro-p` on the remote PATH. The alternative is the Linux build under WSLg. Either way the vendor desktop apps lose sight of the sessions.
- **Partners** (all not screened out):
  - **Tailscale** (tailwind): the phone reaches `http://<pc-tailnet-name>:<port>/<token>`, plus F6 via Serve.
  - **agentsview** (agentview-b): A2 full record of every Maestro-launched session, including Auto Run, and an archive that outlives Claude's cleanup.
  - Optional **claude-desktop**: approval-gated Claude work from the iPhone through the Claude app and Remote Control, and F10 through `claude --desktop --resume`.
  - Optional **chatgpt-desktop-codex**: F10 for Codex, if exec threads list there.
  - No sync partner is needed for A5. Obsidian Sync or GitHub could add F8 for non-image files.
- **Conflicts:**
  - Don't drive the same session from Maestro and a vendor TUI or Desktop at the same moment; take over only when the tab is idle.
  - Maestro's Codex usage panel reads `auth.json` (policy risk); leave it unused.
  - Group Chat's "Only work with agents that are free" default should stay on, to avoid two processes editing the same files.

## Open questions
- **Will a release send Claude permission requests to web clients?** The fix would route `process:permission-request` through `safeSend`, the bridge fan-out. That would move A1 (ii) for Claude, and the screen, to PASS; check the next release's `src/main/permission-relay/integration.ts`.
- **Can Full Access avoid the `AskUserQuestion` stall?** Passing a custom arg such as `--disallowedTools AskUserQuestion` might make Claude ask in plain text, which the phone can answer by message. That would support a configuration-scoped PASS (7.16c) only if documented or demonstrated; I found neither.
- **Tailscale reach is shown by source and an issue, not by Maestro's docs.** A live test would settle it: iPhone on cellular with Tailscale opening `http://<pc-tailnet-name>:<custom port>/<token>`, with Windows Defender Firewall allowing the port. This affects the A1 reach row only. The fallback, the Cloudflare tunnel, would add `cloudflared` as glue, which needs its own N1–N3 screen (7.12).
- **WSL2 topology.** If the repos and CLIs live in WSL2, Windows Maestro must reach them through SSH-remote mode. That mode cannot use Claude Standard permission mode and needs `maestro-p` on the remote PATH. The alternative is Maestro's Linux build under WSLg, which the docs cover only as WSL2 troubleshooting. This does not change C1 (the native Windows build passes), but it matters for A5 and stack design.
- **Billing of `claude --print` under Maestro.** Maestro says "bills per-token API credit"; Anthropic (2026-10-07) says `claude -p` still draws subscription limits, and Max/Team plans also include monthly API credits. A3 holds either way, since it is the user's own plan in the unmodified binary. A stack wanting certainty can pick the "TUI Wrapper (Max plan)" token source. Make sure no `ANTHROPIC_API_KEY` or gateway env is set, because that would be an API-key path (A6a).
- **Mid-turn steering.** "steer a running Claude or Codex turn from a queued message" (#1788, merged 2026-10-11) is after v1.0.0, probably in v1.1.0-RC. Once in a Latest release, it improves (ii) messaging for both harnesses.
- **(Deep-dive) Does the configuration-scoped A1 PASS hold in practice?** The setup is per-agent custom args `--disallowedTools AskUserQuestion` in Full Access mode. Claude's docs say a bare tool name removes the tool. Nothing documents that Claude then asks in plain text instead of guessing. A live test from an iPhone would settle A1 (ii) for Claude under 7.16c.
- **(Deep-dive) F10, Codex half.** Do `codex exec` threads that Maestro launches, in the shared `%USERPROFILE%\.codex`, appear in the ChatGPT desktop app's thread list? If yes, F10 becomes PASS. research/chatgpt-desktop-codex.md leaves the same question open.
- **(Deep-dive) A8 from read-only Codex tabs.** In read-only mode Codex runs with `--sandbox read-only`. Whether `maestro-cli` can still reach the app's local WebSocket from inside that sandbox is untested. A8 is unaffected in the default bypass mode.
- **(Deep-dive) Always-on behaviour.** Maestro has a "power management" setting (General tab) whose exact effect I did not verify. It is unknown whether Maestro and its child agents keep running across Windows screen lock, sleep or signed-out sessions; this matters for C1 operation, not the verdict.
