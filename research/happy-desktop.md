- After the stop point, I read the source to answer the orchestrator's A3/A4 question. The answer is that the candidate would also hard-fail A3/A4 ("can run neither harness per a PASS row of 7.6"):
  - **Codex:** Happy reimplements Codex itself. Its own loop calls `chatgpt.com/backend-api/codex` with the user's ChatGPT OAuth token from `~/.codex/auth.json`, refreshes that token under Codex's OAuth client ID, and sends `originator: codex_exec`. That is a non-native harness on the plan: A4 FAIL (7.6) and A3 FAIL (7.16b).
  - **Claude:** it uses the Claude Agent SDK on the user's own Claude Code login. It replaces the system prompt ("You are Happy Agent, built by Happy") and disables every built-in tool, substituting Happy's own tools over MCP. No setting restores the `claude_code` preset, so A4 is PARTIAL under 7.6 and 7.16d.
- With the original CLI already failing N3 (research/happy.md), no Happy PC component can enter a stack. Only the iOS app and relay pass the NEVER gates, and both need a PC component.

### Harness integration from source (recorded after the stop point; not gate verdicts)
The orchestrator asked for this, and it shows that the outcome does not depend on how N1 is read. Abbreviations: `A/` = `https://github.com/slopus/happy-agent/blob/a6564fa8a4284bb951b1ff4039a2e202113e08ee/` (v0.4.100). `P/` = `A/packages/happy-providers/sources/vendors/`. `D/` = `https://github.com/slopus/happy-desktop/blob/01d78f1d4611d32c60560d19fe5d2ef1a366c966/` (v0.0.98).

- **What "Happy runs the harness itself" means.** Happy Agent is "an open-source coding-agent harness built on top of Pi's foundations" that "recreates" Codex, Claude Code and Grok Build. Happy Desktop is a client of that daemon: it "runs on it and connects through `@slopus/happy-agent-client`" ([A/README.md#L36-L46](https://github.com/slopus/happy-agent/blob/a6564fa8a4284bb951b1ff4039a2e202113e08ee/README.md#L36-L46)). Each provider row in "How it works" pairs a vendor transport with "Reimplemented … prompts, tool contracts …" ([A/README.md#L151-L152](https://github.com/slopus/happy-agent/blob/a6564fa8a4284bb951b1ff4039a2e202113e08ee/README.md#L151-L152)).
- **Codex: Happy's own agent loop on the user's ChatGPT OAuth token** (matches 7.6's "non-native harness on the user's ChatGPT or Claude plan" row).
  - The README says: "The Codex integration is implemented inside Happy Agent rather than wrapping the Codex CLI" ([A/README.md#L157-L160](https://github.com/slopus/happy-agent/blob/a6564fa8a4284bb951b1ff4039a2e202113e08ee/README.md#L157-L160)). The provider package depends on the plain `openai` SDK and `@anthropic-ai/claude-agent-sdk`. It has no Codex SDK ([A/packages/happy-providers/package.json#L49-L58](https://github.com/slopus/happy-agent/blob/a6564fa8a4284bb951b1ff4039a2e202113e08ee/packages/happy-providers/package.json#L49-L58)).
  - It reads `$CODEX_HOME/auth.json`, or `~/.codex/auth.json` by default ([P/codex/impl/auth.ts#L43-L50](https://github.com/slopus/happy-agent/blob/a6564fa8a4284bb951b1ff4039a2e202113e08ee/packages/happy-providers/sources/vendors/codex/impl/auth.ts#L43-L50)).
  - For a `codex-session` credential, the endpoint is `https://chatgpt.com/backend-api` ([P/codex/CodexProvider.ts#L84-L92](https://github.com/slopus/happy-agent/blob/a6564fa8a4284bb951b1ff4039a2e202113e08ee/packages/happy-providers/sources/vendors/codex/CodexProvider.ts#L84-L92), [P/codex/impl/codexConstants.ts#L1-L2](https://github.com/slopus/happy-agent/blob/a6564fa8a4284bb951b1ff4039a2e202113e08ee/packages/happy-providers/sources/vendors/codex/impl/codexConstants.ts#L1-L2)).
  - It builds `new OpenAI({ apiKey: <ChatGPT access token>, baseURL: "<endpoint>/codex", defaultHeaders: { "chatgpt-account-id", originator: "codex_exec", "user-agent", "x-codex-installation-id", … } })` ([P/codex/impl/createCodexClient.ts#L89-L115](https://github.com/slopus/happy-agent/blob/a6564fa8a4284bb951b1ff4039a2e202113e08ee/packages/happy-providers/sources/vendors/codex/impl/createCodexClient.ts#L89-L115)).
  - The user-agent string is `codex_exec/<version> (…)`, with the version read from the installed `codex --version` ([P/codex/impl/codexUserAgent.ts#L12-L40](https://github.com/slopus/happy-agent/blob/a6564fa8a4284bb951b1ff4039a2e202113e08ee/packages/happy-providers/sources/vendors/codex/impl/codexUserAgent.ts#L12-L40)). The installed binary is used only for that version number.
  - It refreshes the token itself at `https://auth.openai.com/oauth/token` under client ID `app_EMoamEEZ73f0CkXaXp7hrann` ([P/codex/CodexSessionCredential.ts#L58-L66](https://github.com/slopus/happy-agent/blob/a6564fa8a4284bb951b1ff4039a2e202113e08ee/packages/happy-providers/sources/vendors/codex/CodexSessionCredential.ts#L58-L66)). It then writes the rotated tokens back into Codex's `auth.json` ([P/codex/impl/refreshCodexAuthFile.ts#L42-L89](https://github.com/slopus/happy-agent/blob/a6564fa8a4284bb951b1ff4039a2e202113e08ee/packages/happy-providers/sources/vendors/codex/impl/refreshCodexAuthFile.ts#L42-L89)).
  - **There is no native alternative.** I grepped both repos' `packages/` for `codex app-server`, the Codex SDK, ACP and spawning `codex`, and found none. Codex provider instances accept only `auth_file`, `base_url` and `transport` ([A/docs/configuration.md#L642-L644](https://github.com/slopus/happy-agent/blob/a6564fa8a4284bb951b1ff4039a2e202113e08ee/docs/configuration.md#L642-L644)). 7.16c therefore cannot apply.
  - **Grade if reached:**
    - A4 FAIL and F1 FAIL (7.6, non-native harness row).
    - A3 FAIL (7.16b: "uses the plan credentials for inference outside the native harness").

  - The README says Happy "calls the official Claude Agent SDK directly for inference, but disables its built-in tools, skills, slash commands, and filesystem settings. Happy Agent then supplies its own implementations of those surfaces" ([A/README.md#L162-L166](https://github.com/slopus/happy-agent/blob/a6564fa8a4284bb951b1ff4039a2e202113e08ee/README.md#L162-L166)).

## Open questions
- **N1 attribution.** Should Happy be judged as one product on slopus/happy's 24k stars? The App Store app and the brand live there, and the desktop README presents four repos as one product.
  - The brief (7.3: "the repo that holds the source") and the task ("the stars of the repo that holds the successor's source") both point at slopus/happy-desktop and slopus/happy-agent, so N1 FAIL stands.
  - Under the alternative reading, only N1 changes. The outcome would move to FAIL at the first of N2, C1, A1 and A3/A4 to hard-fail, and the source above already meets 7.11's A3/A4 hard-fail condition.
- **Future re-screen.** Both repos are about three months old. A re-screen is worth doing only if both of these change: (a) each repo passes 1,000 stars (would flip N1), and (b) Happy Agent gains a Codex provider built on `codex app-server`, the Codex SDK or the `codex` binary, plus a supported setting that keeps Claude's `claude_code` preset and built-in tools (would move A4/A3 under 7.6 and 7.16c). Neither (b) change exists at v0.4.100 or `main` `5b9bf3c`.
- **Anthropic policy conflict, not decided here.** Anthropic's Legal page tells developers using the Agent SDK to "use API key authentication". The newer dated Help Center update (2026-10-07) says the Agent SDK and third-party apps can still use subscription limits. 7.14 favours the dated page; resolve.md §B.8 records the same split. This would matter only for the Claude path's A3, which does not affect the outcome.
