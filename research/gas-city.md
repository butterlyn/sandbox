## Summary
- Screen: SCREEN HOLD (A1)
- Deep-dive (2026-10-19, deepdive-gas-city, v1.5.0 `f664746`):
  - **Component-level ALWAYS gates:**
    - PASS: A2, A3, A4, A6, A7 (sandbox clause not exercised) and A8.
    - **A8 is first-class** through the platform's own CLI. The official tutorial shows a Claude "mayor" running `gc sling` to a Codex reviewer.
    - A1 PARTIAL.
    - A5 FAIL: there is no file browsing, so a partner is required.
  - **FAVOUR:** F1–F10 = 3/20; F11a–e = 8/10.
  - **Fact that most affects composition:** Gas City is strong on delegation and audit, weak on the phone. The only documented remote view is a read-only dashboard. Claude sessions could reach the Claude iOS app through `remoteControlAtStartup` (untested). Codex sessions have no screened phone path. The `t3bridge` route into T3 Code's iOS app is undocumented and unverified against T3 v0.1.0.
- **Project health: healthy, with several maintainers.** Not archived. v1.5.0 shipped 2026-10-05, and `main` has 2,095 commits since 2026-07-21; the last non-bot commit was on 2026-10-19. It has 1.4k stars. Since 2026-04-22, Julian Knutsen wrote 51.7% of non-bot commits and Jim Wordelman 15.6%. Chris Sells and Stephanie Jarmak have also merged other people's PRs. N3, N1 and N2 PASS.
- **PC side: runs in WSL2.** There are official Linux builds (tarballs and Homebrew), and the docs say "Gas City works under WSL 2 with a standard Ubuntu or Debian distribution". The supervisor runs unattended as a systemd user service. There is no native Windows build. C1 is `PASS (via WSL2)`.
- **Harnesses: both are native.** The default runtime is tmux. It starts the unmodified `claude` and `codex` interactive TUIs in detached tmux panes, using the user's own logins. On that path, Gas City never reads Claude credential files. Its onboarding probe insists on first-party claude.ai or `oauth_token` auth for Claude and on ChatGPT auth for Codex. A3 and A4 PASS.
  - Caveats the stack must avoid, under 7.16c:
    - an optional Kubernetes path copies `~/.claude/.credentials.json` into a K8s Secret;
    - any `ANTHROPIC_API_KEY` in the environment is accepted automatically, and the docs' `secrets.env` example uses API keys;
    - the readiness probe reads Codex `auth.json` locally (see the policy-risk note below).
  - ACP: Gas City ships no adapter for either harness.
- **Phone access: partial (A1).** The Stage 1 lead said there was no dashboard. That is wrong: v1.5.0 has a built-in web dashboard. It lists sessions with live peeks and transcripts, can approve or deny Claude prompts, and can create a bead and dispatch ("sling") it to a chosen agent and rig. It cannot message a running session (the code calls that route read-only on purpose), and it does not detect Codex prompts. It also binds to loopback by default and is "intended for local, single-operator use". Write access from a phone needs an unauthenticated write plane. Because sessions live in tmux, the 7.4 generic-terminal path is open, but it needs a screened iOS terminal app as a partner component.
- **What would settle the HOLD:** any one of these.
  - A stack-level A1 PASS through a screened iOS SSH or mosh app, plus a network path, that attaches to Gas City's tmux sessions.
  - A Gas City release whose dashboard sends session messages (the API already has the endpoints), handles Codex prompts, and documents authenticated remote access.
  - Documented support for the `t3bridge` runtime, which would put Gas City sessions in T3 Code's iOS app.

**Credential-handling policy risk (7.16b, required).**
- **Vendor policies.**
  - Anthropic: "developers may not collect, store, or intermediate Claude.ai credentials or session tokens — sign-in to a Claude account must complete through Anthropic's own flow." The same page allows "an end user … signing in to the unmodified Claude Code binary with their own Claude subscription" (https://code.claude.com/docs/en/legal-and-compliance, undated, retrieved 2026-10-19).
  - OpenAI: "treat `~/.codex/auth.json` like a password: it contains access tokens" (https://learn.chatgpt.com/docs/auth, undated, retrieved 2026-10-19).
- **What Gas City does with vendor credentials:**
  - **Codex `auth.json`, read locally.** The readiness probe reads `~/.codex/auth.json` only to check `auth_mode` and whether any token field is non-empty ([L420-L451](https://github.com/gastownhall/gascity/blob/f66474617d2bb7fbe51a3d746da5f3ceab2b8517/internal/api/handler_provider_readiness.go#L420-L451)). Nothing is sent anywhere, and Gas City never sets `CODEX_HOME` or copies the file. Under 7.16b this is a side read: A3 is unaffected, and F1 is at most PARTIAL for Codex. A side effect: with `cli_auth_credentials_store = keyring` the probe would wrongly report "missing ~/.codex/auth.json".
  - **Claude credentials, default path.** Gas City does not touch them. The probe runs `claude auth status --json`.
  - **Claude credentials, forwarded env vars.** If the user sets `CLAUDE_CONFIG_DIR` or `CLAUDE_CODE_OAUTH_TOKEN`, Gas City forwards them into sessions ([processenv L180-L196](https://github.com/gastownhall/gascity/blob/f66474617d2bb7fbe51a3d746da5f3ceab2b8517/internal/processenv/provider.go#L180-L196)). It also writes them into the supervisor's launchd/systemd service file ([L1343-L1357](https://github.com/gastownhall/gascity/blob/f66474617d2bb7fbe51a3d746da5f3ceab2b8517/cmd/gc/cmd_supervisor_lifecycle.go#L1343-L1357)). That file is a local copy of a token the user minted (7.6 row 2: A3 and A4 PASS, F1 PARTIAL).
  - **Kubernetes runtime (optional, source build).** `make k8s-secret CLAUDE_CONFIG_SRC=~/.claude` copies `.credentials.json`, the claude.ai OAuth tokens, into a K8s Secret `claude-credentials`. Every pod mounts that Secret and copies it into `$HOME/.claude` ([Makefile L1109-L1130](https://github.com/gastownhall/gascity/blob/f66474617d2bb7fbe51a3d746da5f3ceab2b8517/Makefile#L1109-L1130), [pod.go L257](https://github.com/gastownhall/gascity/blob/f66474617d2bb7fbe51a3d746da5f3ceab2b8517/internal/runtime/k8s/pod.go#L257), [L313-L322](https://github.com/gastownhall/gascity/blob/f66474617d2bb7fbe51a3d746da5f3ceab2b8517/internal/runtime/k8s/pod.go#L313-L322)). On a local cluster this is a local copy. On a remote cluster the tokens leave the machine for a non-vendor server, which is an A3 FAIL for that path. The stack must not use the k8s runtime with plan credentials. Pods get no Codex credentials.
  - **API-key fallback hazard.**
    - The troubleshooting doc's `~/.gc/secrets.env` example is `ANTHROPIC_API_KEY=sk-ant-...` / `OPENAI_API_KEY=sk-...`. `gc` merges `ANTHROPIC_*`/`OPENAI_*` variables from the shell and that file into the supervisor environment ([L408-L446](https://github.com/gastownhall/gascity/blob/f66474617d2bb7fbe51a3d746da5f3ceab2b8517/docs/getting-started/troubleshooting.md#L408-L446)).
    - When Claude asks whether to use a detected API key, the tmux dialog handler answers "Yes" (Up, Enter) automatically ([dialog.go L1329-L1354](https://github.com/gastownhall/gascity/blob/f66474617d2bb7fbe51a3d746da5f3ceab2b8517/internal/runtime/dialog.go#L1329-L1354)), so the session silently bills the API.
    - The stack setup must keep both keys unset, or set `GC_SUPERVISOR_OMIT_PROVIDER_CREDS=1`. This matters for A6a ("no API-key fallback configured").
  - **No impersonation.** Gas City has no claude.ai login of its own, no user-agent spoofing and no proxying.
- **Strict alternatives.**
  - 7.16b strict ("any third-party read of Claude OAuth tokens fails A3 for the Claude path"): the default path is unaffected.
  - 7.16c strict ("offering a non-compliant … credential path at all fails A3"): the `k8s-secret` target is a Claude credential-copy path. It would make the Claude path FAIL and component A3 PARTIAL, which would add A3 to the HOLD.

### Harness integration (from source)
- **How it invokes `claude`.**
  - `tmux new-session -d … claude` with mode flags (default `--dangerously-skip-permissions`), `--session-id <uuid>` (later `--resume <uuid>`), `--settings <city>/.gc/settings.json` (hooks only) and the prompt.
  - One-shot `claude -p` is used only for titles and prompt synthesis.
  - Permalinks: Screen A4.
- **How it invokes `codex`.**
  - `codex --dangerously-bypass-approvals-and-sandbox --model gpt-5.5 <prompt>`, resumed with `codex resume`.
  - Role context arrives via `.codex/hooks.json`.
  - Neither path replaces the base instructions (7.16d).
- **Permissions.** Both harnesses default to unrestricted modes, so permission prompts rarely appear. This is a security posture to choose deliberately.
- **OAuth credentials.**
  - Claude: none read on the default path (the probe uses `claude auth status --json`). `CLAUDE_CONFIG_DIR` and `CLAUDE_CODE_OAUTH_TOKEN` are forwarded only if the user sets them. The k8s Makefile target copies `.credentials.json` into a Secret.
  - Codex: `auth.json` is read locally for a presence check.
  - None: no proxying, no user-agent spoofing, no own login.
  - The 7.16b "Credential-handling policy risk" note is in the Screen section above and still holds.
- **Transcripts.**
  - Native, in WSL2 `~/.claude/projects` and `~/.codex/sessions`.
  - Gas City's own state (beads, mail, events) lives in its bd/dolt store.
